# genomic-range-overlap-statistics

## Summary

Quantify enrichment of genomic range overlaps by comparing an observed overlap statistic (e.g. the proportion of SNPs with peaks within 10 kb) against a block-bootstrapped null distribution generated with bootRanges, yielding per-iteration rates, their variance, and a z-score. This preserves local genomic correlation structure, avoiding the over-estimated significance produced by simple shuffling.

## When to use

Use when testing whether an observed overlap between two genomic range sets (e.g. caQTL/SNP sets and peaks, or CREs and genes) is significant relative to a null that accounts for genomic structure, using GRanges objects in R/Bioconductor.

## When NOT to use

- When the goal is only raw overlap counts without significance testing against a null distribution (e.g. simply counting DEGs vs differential accessibility peaks before spline fitting in macrophage.R)
- When the comparison method is already a valid structured null (e.g. timing benchmarking bootRanges vs GSC runtime, as in bootranges_vs_GSC.R, needs no overlap z-score)
- When range sets are non-genomic tabular data that cannot be represented as GRanges objects

## Inputs

- Observed query ranges as GRanges (e.g. caQTLs / SNPs associated with total cholesterol from human liver ATAC-seq)
- Target feature ranges as GRanges (e.g. ATAC-seq peaks)
- Block-bootstrapped null range sets generated by bootRanges (segmental blocks matched to segmentation-derived block lengths)
- Overlap window threshold (10 kb)

## Outputs

- Per-bootstrap-iteration overlap rates
- Across-replicate variance of the overlap rate
- Z-score of the observed overlap rate relative to the bootstrap null
- overlap_rate_zscore.tsv

## How to apply

Construct GRanges objects for the observed query and target ranges, preprocessing as in GRanges_construct.R. Generate block-bootstrapped null range sets with bootRanges (segBootranges.R step) using segmental blocks derived from a segmentation so local correlation structure is preserved. For each bootstrap iteration b, count SNPs whose range overlaps a peak within a 10 kb window and divide by the total number of SNPs to get the per-iteration overlap rate; pool the Lb rates and compute their variance (var.R). Standardize the observed rate as the z-score: (observed rate minus mean of the Lb null rates) divided by the null standard deviation, and write per-iteration rates, variance, and z-score to overlap_rate_zscore.tsv. As a rationale, block bootstrap creates new range sets that preserve local genomic correlation structure and generate more reliable null distributions, whereas shuffling or permutation schemes may give overly narrow nulls and over-estimated significance.

## Related tools

- **bootRanges** (Generates block-bootstrapped null sets of genomic ranges preserving local genomic correlation structure, against which the observed overlap rate is standardized) — https://bioconductor.org/packages/nullranges
- **nullranges** (R/Bioconductor package hosting bootRanges; used with plyranges to load and overlap GRanges objects in the var.R workflow step) — https://bioconductor.org/packages/nullranges

## Examples

```
Rscript var.R  # pools per-iteration overlap rates, computes across-replicate variance and z-score, writes overlap_rate_zscore.tsv
```

## Evaluation signals

- Per-iteration overlap rates are defined as the fraction of SNPs whose range overlaps a peak within a 10 kb window, so values must lie in [0, 1]
- The z-score equals (observed rate - mean of Lb null rates) / standard deviation of the null rates; recomputation from the pooled null rates should reproduce it exactly
- The pipeline is complete when overlap_rate_zscore.tsv contains per-iteration rates, variance, and the z-score
- The conventional-shuffling baseline (bootstrap.R) should yield a narrower null distribution than the block bootstrap, consistent with permutation over-estimating significance
- Null range sets must come from segmental blocks matched to the segmentation-derived block lengths used in segBootranges.R

## Limitations

- Shuffling or permutation schemes may result in overly narrow test statistic null distributions and over-estimation of statistical significance, so naive permutation baselines are not a valid substitute
- Null quality depends on the segmentation and block lengths used; the variance of the overlap rate across block lengths must be assessed in the var.R step
- Overlap statistic is specific: it counts SNPs with peaks within a 10 kb window, so changing the window requires re-running the whole bootstrap
