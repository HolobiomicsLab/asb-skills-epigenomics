# sequence-information-content-filtering

## Summary

A deterministic poor-match removal step in the Delila-PY pipeline: sequences from the cycle-2 per-sequence information content computation are dropped with the ri program when they carry ≤0 bits, and the retained set is fed back to delila to regenerate the book before the final motif cycle.

## When to use

Use when a Delila-PY cycle-2 per-sequence information content table (in bits, from alist/encode/cmp/rseq) must be filtered to remove poorly matching sequences before regenerating the book for cycle 3.

## When NOT to use

- Input is a raw GenBank file or tab-delimited sites file (cycle 0 setup) rather than cycle-2 rseq information content values — filtering operates on computed bits, not coordinates
- The goal is the cycle-1 alignment search for highest information content (malign/malin), not removal of individual poor matches
- All sequences already have information content >0 bits, so the ri cutoff would remove nothing and the step adds no value

## Inputs

- Cycle-2 per-sequence information content values (bits) computed by alist, encode, cmp, and rseq
- Delila book of sequences from cycle 2
- Delila library files generated by dbbk and catal from the GenBank file

## Outputs

- Filtered sequence list containing only sequences with information content >0 bits (for feedback to delila)
- Updated delila book file used for the final motif-generation cycle

## How to apply

Load the cycle-2 per-sequence information content values (bits) produced by the alist/encode/cmp/rseq computation into a table. Apply the ri program rule deterministically: retain a sequence only if its information content is >0 bits, and remove it if it is ≤0 bits — the paper defines poorly matching sequences as '≤0 information content'. Write the retained sequences to a filtered sequence list file and run delila with this list plus the library files to generate an updated book file that feeds the final motif cycle (alist, encode, cmp, rseq, dalvec, makelogo). Validate by independently recounting: the number of retained and removed sequences must exactly match applying the ≤0-bit cutoff by hand, and no retained sequence may have information content ≤0 bits.

## Related tools

- **ri** (Applies the ≤0-bit information content cutoff to classify each sequence as retained or removed) — https://github.com/GLBRC/delila
- **rseq** (Produces the per-sequence information content values that the ri cutoff is applied to) — https://github.com/GLBRC/delila
- **delila** (Regenerates the updated book file from the filtered sequence list and library files) — https://github.com/GLBRC/delila

## Evaluation signals

- Number of retained sequences plus number of removed sequences exactly equals the count obtained by independently applying the ≤0-bit cutoff to the input information-content table
- No retained sequence in the filtered list has information content ≤0 bits
- Every removed sequence has information content ≤0 bits (borderline 0-bit sequences must be removed, not retained)
- delila accepts the filtered sequence list and library files and produces a valid updated book file for cycle 3
- The final-cycle artifacts (PWM text file, sequence logo in postscript and PDF, dalvec output) exist after the filtered book is processed

## Limitations

- The cutoff is a hard, deterministic threshold (≤0 bits); the article does not describe any soft or adjustable filtering parameter
- Filtering quality depends entirely on the cycle-2 rseq information content values; errors upstream propagate into retained/removed decisions
- The Delila-PY README documents testing only on MacOS and Linux (Ubuntu and CentOS); other operating systems may require additional work
