# Batch bioinformatics workflow configuration

## Summary

Configure and launch a multi-dataset bioinformatics pipeline run (ChiLin) by generating per-dataset configuration files, listing them in a batch.conf, and executing the 13-step ChIP-seq/DNase-seq QC workflow with 'chilin batch' so tens to thousands of samples are processed with minimal user intervention.

## When to use

Use when many ChIP-seq or DNase-seq FASTQ datasets (treatment plus control, single- or paired-end) must be QC'd and analyzed in batch, with per-sample JSON QC statistics emitted for aggregation.

## When NOT to use

- You need interactive, single-sample point-and-click analysis (e.g. Cistrome/CisGenome/ChIPseeqer GUI solutions) rather than scripted batch execution
- Your data is not ChIP-seq or DNase-seq FASTQ with an appropriate narrow/broad peak type; other assay types fall outside ChiLin's 13-step workflow
- You already have BAM files and only need a single QC metric — dedicated tools like ENCODE phantompeakqualtools or ChIPQC may suffice without full batch configuration

## Inputs

- Single-end or paired-end ChIP-seq/DNase-seq FASTQ files (treatment and control) from GEO-deposited datasets
- Per-dataset config files generated by 'chilin gen' ([basics] section: species, FASTQ paths, narrow/broad peak type)
- batch.conf file listing per-dataset config paths
- Species reference data: genome index, chrom_len, DHS/blacklist, geneTable (hg19/hg38/mm9/mm10 tgz); optional PhastCons conservation bigwigs and Mycoplasma fasta

## Outputs

- Per-sample QC JSON statistics (id_fastqc., id_map., id_frag., id_pbc., id_frip., id_macs2., id_rep., etc.)
- Plain-text and tabular QC summary covering 17 metrics across three QC layers per sample and dataset
- Mapped BAM files, called peaks (narrow/broad), and meta-region annotation from bedAnnotate.py

## How to apply

For each dataset run 'chilin gen' to create a per-dataset config, filling the [basics] section with species, treatment/control FASTQ paths, and narrow/broad peak type, and confirming species reference data (genome index, chrom_len, DHS/blacklist, geneTable; hg19/hg38/mm9/mm10 tarballs from cistrome.org). List the per-dataset config paths in a batch.conf file and launch with 'chilin batch -b batch.conf', which runs the 13-step workflow: FastQC quality/GC/contamination evaluation, bwa (default; bowtie or star alternative) mapping, macs2 fragment-size estimation, PBC evaluation, replicate peak overlap/correlation, merged peak calling, FRiP scores, bedAnnotate.py meta-region annotation, and optional PhastCons conservation, regulatory-potential, and MDSeqPos motif steps (MDSeqPos auto-skipped for fewer than 200 peaks). Parse the emitted per-sample JSON stats (id_fastqc., id_map., id_frag., id_pbc., id_frip., id_macs2., id_rep.) and aggregate with the qc__summary / qc_summary_table modules covering 17 QC metrics across three QC layers. Versions used in the reference environment include bwa 0.7.13, samtools 0.1.19, bedtools 2.17.0, macs2 2.1.0, and FastQC installed via conda into a python=2 chilin_env.

## Related tools

- **ChiLin** (Pipeline orchestrator: 'chilin gen' creates per-dataset configs, 'chilin batch -b batch.conf' runs the 13-step QC/analysis workflow and emits per-sample QC JSON) — https://github.com/cfce/chilin

- **MDSeqPos** (Optional step 12 motif analysis on called peaks; skipped automatically when peaks number fewer than 200) — https://bitbucket.org/cistrome/cistrome-applications-harvard

## Examples

```
chilin gen && chilin batch -b batch.conf
```

## Evaluation signals

- The batch run emits per-sample QC JSON files for every expected metric id (id_fastqc., id_map., id_frag., id_pbc., id_frip., id_macs2., id_rep.) with no missing samples
- The aggregated summary table contains 17 QC metrics across three QC layers for every sample and dataset, matching Additional file 2: Table S1 (23,677 samples from 11,265 datasets in the reference atlas)
- Steps 2 (mapping) and 6 (merged peak calling) produced output for all datasets, since the article marks these as 'cannot be skipped'
- Steps 1, 3-5, and 7-13 are either completed or explicitly skipped per the documented dependency rules (e.g. PBC evaluation skipped if step 3 ran; MDSeqPos skipped for < 200 peaks)
- The demo run (bash demo/docker_test.sh) or demo/foxa1 test completes and results can be copied out with 'docker cp container_id:/chilin/local .'

## Limitations

- Step 2 (mapping) and step 6 (merged peak calling) cannot be skipped; all other steps have documented skip/dependency rules that a misconfigured batch.conf can violate
- MDSeqPos motif analysis is skipped automatically when peaks number fewer than 200
- Requires python 2 environment and pinned older tool versions (bwa 0.7.13, samtools 0.1.19, bedtools 2.17.0, macs2 2.1.0); no software version is stated in the article itself, which complicates exact reproduction
- Pipeline assumes reference-dependent data (genome index, chrom_len, DHS/blacklist, geneTable) is downloaded per species; missing reference files break per-dataset configs
