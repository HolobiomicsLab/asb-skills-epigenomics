# workflow-container-initialization-sprproject

## Summary

Initializes a systemPipeR workflow container with SPRproject() to set up project logging, environment, and metadata (SPRproject object) before importing and running NGS workflow steps such as the pre-configured RNA-Seq template. It is the mandatory first runtime step of systemPipeR's genWorkenvir/SPRproject → importWF → runWF → renderReport lifecycle.

## When to use

Use when starting execution of a systemPipeR workflow (e.g., the RNA-Seq template in a freshly generated spr_project directory) and a workflow container with logging must be created before importWF/runWF can be called.

## When NOT to use

- No systemPipeR working environment exists and no NGS workflow (RNA-Seq, ChIP-Seq, VAR-Seq, Ribo-Seq) is being run — the container only has meaning inside a genWorkenvir-generated project
- The analysis is a single standalone R script or external CLI invocation outside systemPipeR's workflow management, where container initialization and step logging add no value
- The user only needs pre-configured workflow templates for NGS applications that the article states are still under development and not yet available

## Inputs

- Working environment generated by genWorkenvir(work = "rnaseq") containing a spr_project directory with parameter files and the systemPipeRNAseq.Rmd template
- systemPipeR R/Bioconductor environment (R >= 3.2, Bioconductor >= 3.2 per article discussion)

## Outputs

- SPRproject workflow container object with project logging initialized
- Workflow log/status files within the project directory tracking step execution
- Post-run artifacts: rendered systemPipeRNAseq.html report via renderReport() and run diagnostics via renderLogs()

## How to apply

After generating the working environment with genWorkenvir(work = "rnaseq"), call SPRproject() inside the project directory to initialize the workflow container, creating the project logging and environment that track step status. Then import executable steps from the R Markdown template with importWF("systemPipeRNAseq.Rmd"), which parses R Markdown chunks into workflow steps. Execute the imported steps with runWF() on a local machine or cluster, then render diagnostics and scientific output via renderReport() and renderLogs(). The rationale is systemPipeR's design as a Bioconductor package uniting R/Bioconductor resources with external command-line software, so the container must exist to record each step for reproducible automated report generation.

## Related tools

- **systemPipeR** (Provides SPRproject(), importWF(), runWF(), renderReport(), and renderLogs() used to initialize, populate, execute, and report the workflow container) — http://bioconductor.org/packages/devel/systemPipeR
- **R** (Programming language runtime in which the workflow container is initialized and the workflow steps execute)
- **Bioconductor** (Distribution channel for the systemPipeR package used for this skill) — http://bioconductor.org/packages/devel/systemPipeR

## Examples

```
library(systemPipeR); SPRproject(); importWF("systemPipeRNAseq.Rmd"); runWF(); renderReport(); renderLogs()
```

## Evaluation signals

- SPRproject() completes and returns a workflow container object with project logging initialized inside the spr_project directory
- importWF("systemPipeRNAseq.Rmd") parses the R Markdown chunks into executable workflow steps without errors
- runWF() completes all imported steps without errors
- The HTML report file systemPipeRNAseq.html is rendered by renderReport() and exists on disk
- renderLogs() produces run diagnostics reflecting the executed steps

## Limitations

- Version constraints (R >= 3.2, Bioconductor >= 3.2) may limit reproducibility with newer environments
- Workflow templates for additional NGS applications are under development and not yet available
- The container is tied to systemPipeR's R Markdown chunk-parsing (importWF) step-import format; arbitrary scripts must be wrapped as workflow steps to be tracked
