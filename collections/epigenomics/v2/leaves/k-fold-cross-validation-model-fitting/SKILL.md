# k-fold cross-validation model fitting

## Summary

Train DriverPower's gradient boosting machine (XGBoost) background mutation rate (BMR) model using k-fold cross-validation (default 3 folds, two folds train and one validates each fold model), as an alternative to the randomized-lasso GLM, to predict regional mutation burden on held-out 1-Mbp test elements.

## When to use

Use when training a DriverPower BMR model on per-element response tables (nMut, nSample, length) with an HDF5 feature matrix of 1373 genomic features and you need a nonlinear, cross-validated fit whose generalization you will assess on held-out test elements.

## When NOT to use

- You only need a sparse, interpretable linear background model — DriverPower's GLM path with randomized lasso feature selection (--featImpCut on feature importance) is the article's alternative to GBM
- Input features have not yet been assembled into a single HDF5 matrix — the 3-part train_feature.hdf5 split must be concatenated and md5-verified first
- The goal is driver calling rather than BMR model fitting — use 'driverpower infer' with a pre-trained model instead of 'driverpower model'

## Inputs

- Merged training feature matrix train_feature.hdf5 (3-part split; md5 cb4af6bc7979efa087955f94909dd065) with 1373 genomic features for 867,266 training elements
- Per-element training response table train_y.tsv (nMut, nSample, length) generated by prepare.py from somatic mutations, element BEDs, and callable regions
- DriverPower model sub-command parameters: --method GBM, --gbmFold 3, --name, --modelDir

## Outputs

- Serialized GBM model file modelDir/<name>.GBM.model.pkl (e.g. ./output/tutorial.GBM.model.pkl)
- feature_importance.tsv listing feature importance scores from the fitted folds
- model_info.pkl with model metadata
- Training log lines reporting 'Model metrics for training set: r2=..., Variance explained=...'

## How to apply

First generate per-element response tables with prepare.py (e.g. 'python ./prepare.py random_mutations.tsv.gz train_elements.tsv.gz callable.bed.gz train_y.tsv') and merge the three-part training feature matrix ('cat train_feature.hdf5.part1 train_feature.hdf5.part2 train_feature.hdf5.part3 > train_feature.hdf5', md5 cb4af6bc7979efa087955f94909dd065). Then run the DriverPower 'model' sub-command with --method GBM and --gbmFold 3 (fold must be an integer >= 2; default is 3), which trains 3-fold gradient boosting machines via XGBoost where two folds train and one validates each fold model; XGBoost parameters can be tuned per the dmlc parameter documentation. The training log reports model metrics (the tutorial run shows 'Model metrics for training set: r2=0.63, Variance explained=0.63'), and default outputs include feature_importance.tsv and model_info.pkl (e.g. tutorial.GBM.model.pkl). Rationale: the paper reports that GBM/GLM BMR models built from 1373 genomic features explain up to 93% of regional mutation-rate variance on training elements and 83% on the held-out 2521 non-overlapping 1-Mbp test elements, so cross-validated GBM fitting is preferred when generalization to unseen elements matters; a dispersion test on training data (method 'auto') decides model-family selection.

## Examples

```
driverpower model --feature train_feature.hdf5 --response train_y.tsv --method GBM --gbmFold 3 --name tutorial --modelDir ./output
```

## Evaluation signals

- Concatenated train_feature.hdf5 md5sum matches cb4af6bc7979efa087955f94909dd065 before model fitting
- Training log reports 'Model metrics for training set: r2=0.63, Variance explained=0.63' for the tutorial GBM run (3 folds); paper reports up to 93% variance explained on training elements
- Applying the model to the 2521 held-out non-overlapping 1-Mbp test elements yields ~83% of mutation-rate variance explained (Fig. 1c)
- All expected files exist in --modelDir: <name>.GBM.model.pkl, model_info.pkl, and feature_importance.tsv
- --gbmFold is an integer >= 2 (default 3), and each fold model is trained on two folds and validated on the held-out third

## Limitations

- DriverPower's BMR is trained on predominantly neutral regions and does not model negatively selected sites, limiting recall (no driver discovery tool currently models negative selection)
- False-positive driver calls may arise from variant-calling artefacts or biological processes not captured by the BMR model (e.g. regional AID activity); additional BMR features are proposed but not yet incorporated
- GBM model fit on the tutorial data (r2=0.63 on training elements) is lower than the paper's pan-cancer report (~93% training, 83% test variance explained), so expected variance explained depends on cohort and feature/response data quality
