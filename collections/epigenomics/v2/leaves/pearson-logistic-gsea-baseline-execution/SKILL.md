# pearson-logistic-gsea-baseline-execution

## Summary

Executes the three commonly used baseline methods — Pearson correlation analysis, a logistic regression model, and gene set enrichment analysis (GSEA) — on simulated pharmacogenomic data so their TR–drug response identification performance can be benchmarked against RePhine.

## When to use

Use when a new TR–drug response inference method (e.g. RePhine) must be compared fairly against established mRNA- and target-based baselines on the same simulated noise or confounder scenarios.

## When NOT to use

- Real pharmacogenomic data without a known ground-truth TR–drug relationship, since the baselines here are scored against a simulated true TR–drug association
- Cases lacking reliable ChIP-seq target information or with ChIP-seq data having too few targets, where RePhine-style target-based identification (and the GSEA baseline on targets) would be misled

## Inputs

- Simulated pharmacogenomic data (gene expression, copy number, mutation status, cancer type information, pharmacological/drug response profiles) generated by simulation_code.R under noise and confounder scenarios
- Simulated ChIP-seq target data / regulatory potential (RP) scores
- Scenario parameters from File S1
- RePhine R package (version 1.1.0) with R packages glmnet, MASS, lmtest, ppcor, psych, ROCR

## Outputs

- simulation_benchmark.csv with per-scenario, per-method identification performance (RePhine vs Pearson correlation, logistic regression, GSEA)
- Per-method TR–drug response association rankings / significance scores (uniP, multiP, partial correlations, GSEA enrichment results)

## How to apply

Obtain the RePhine R package and simulation R scripts from github.com/coexps/RePhine (simulation_code.R simulates TR and target expression data, noise data and RP scores), and run it under the added-noise and added-confounder scenarios defined in File S1. On each generated synthetic dataset (gene expression, copy number, mutation status, cancer type, pharmacological profiles plus ChIP-seq/RP scores), apply RePhine and then the three baselines with identical inputs: Pearson correlation between TR mRNA levels and drug response, a logistic regression model of response on TR expression, and GSEA on the target correlation patterns. Score each method by identification performance — detection of the true simulated TR–drug relationship versus false positives and false negatives. Assemble per-scenario, per-method performance into simulation_benchmark.csv; the validation criterion is that RePhine achieves higher identification performance than all three baselines under both scenarios.

## Related tools

- **RePhine** (Reference method whose performance the three baselines are benchmarked against on the simulated data) — https://github.com/coexps/RePhine
- **R** (Runtime environment for simulation_code.R and for executing the regression (logistic), correlation and GSEA baselines; packages glmnet, MASS, lmtest, ppcor, psych, ROCR) — https://github.com/coexps/RePhine

```
Rscript simulation_code.R
```

## Evaluation signals

- The benchmark table must show RePhine with higher identification performance than Pearson correlation, logistic regression and GSEA in the added-noise scenario
- The benchmark table must show RePhine with higher identification performance than all three baselines in the added-confounder scenario
- Simulation data must contain the spurious (non-TR-mediated) correlations intended by the confounder scenario before baselines are run
- All four methods receive identical simulated inputs (expression, drug response, and target/RP data) per scenario
- The R session includes the prerequisite packages glmnet, MASS, lmtest, ppcor, psych and ROCR so the logistic regression and correlation computations run without error

## Limitations

- Inherent experimental noises in real data make mRNA-based predictions not always sufficiently robust, which is why simulation-based benchmarking is used
- Solely relying on mRNA levels of TRs (as the Pearson and logistic baselines do) lacks identification power (false negatives) and may yield inaccurate associations (false positives)
- Baselines on simulated data still require follow-up TR knockout/activation experiments with drug response testing to establish causality
