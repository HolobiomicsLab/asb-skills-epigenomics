# reference-implementation-output-validation

## Summary

Validates a reimplementation of DMRfinder's combine_CpG_sites.py clustering step by diffing the self-produced clustered region/counts table against the reference implementation's output (combined.csv) run on identical inputs.

## When to use

Use when re-implementing or modifying combine_CpG_sites.py and you must prove the new clustered-region table (chr/start/end/CpG plus per-sample -N/-X columns) matches DMRfinder's reference output exactly.

## When NOT to use

- The goal is DMR discovery (findDMRs.r) rather than verifying the clustering/region-merging step itself
- Input files are raw Bismark SAM/BAM alignments rather than the per-site .cov count tables the clustering step consumes
- Intentionally altered parameters (e.g., different -d, -c, -x thresholds) make byte-level identity with a default-parameter reference output impossible

## Inputs

- Per-sample .cov methylation-count tables from extract_CpG_data.py (tab-delimited: chromosome, position, methylated counts, unmethylated counts)
- Reference implementation output: combined.csv generated by combine_CpG_sites.py with identical parameters

## Outputs

- Independently computed clustered-region table (chr/start/end/CpG plus per-sample -N/-X columns)
- output_matches_reference check result (pass/fail diff against combined.csv)

## How to apply

Run the reference tool, combine_CpG_sites.py (jsh58/DMRfinder), on the same per-sample .cov methylation-count tables produced by extract_CpG_data.py using default parameters (-v -o combined.csv). Reproduce the clustering independently in Python: determine valid CpG sites per sample with coverage thresholds -r 3 and -s 1, cluster valid sites by modified single-linkage clustering with max inter-site distance -d 100, require -c 3 CpGs per region, and split any region longer than -x 500 bp into subregions that must still meet the minimum CpG count. Sum methylated and total counts per region per sample, writing NA for samples whose regional total falls below -m 20, and format the output as chromosome/start/end/CpG plus sample-wise -N (methylated) and -X (unmethylated/total) columns. The decisive check is an output_matches_reference comparison: the regenerated table and summed counts must be identical to the reference combined.csv; any row, coordinate, or count mismatch indicates the clustering logic (e.g., subregion splitting or NA handling) diverges from the reference.

## Related tools

- **DMRfinder** (Provides the reference combine_CpG_sites.py whose output serves as the gold standard for the output_matches_reference diff) — https://github.com/jsh58/DMRfinder
- **extract_CpG_data.py** (Produces the per-sample methylation-count .cov tables that are the common input to both the reimplementation and the reference run) — https://github.com/jsh58/DMRfinder
- **Python** (Language used to reimplement the modified single-linkage clustering and regional count summation for comparison)

## Examples

```
python combine_CpG_sites.py -v -o combined.csv C1.cov C2.cov E1.cov E2.cov
```

## Evaluation signals

- output_matches_reference: the independently generated clustered-region table is identical to the reference combined.csv
- Every region satisfies the parameter constraints: at least 3 CpGs (-c 3), inter-site gaps ≤ 100 bp (-d 100), and region length ≤ 500 bp (-x 500)
- Rows where a sample's regional total counts fall below -m 20 carry NA rather than a numeric methylation value
- Column schema matches the reference: chromosome, start, end, CpG count, then paired -N/-X columns per sample in input order
- Regional methylated and total counts equal the sum of the underlying per-site counts from the input .cov tables

## Limitations

- Comparison is only valid when both implementations use identical parameters and identical input count tables; defaults (-r 3, -s 1, -d 100, -c 3, -x 500, -m 20) must match
- Because clustering uses only CpG site locations and never methylation levels, validation cannot detect methylation-driven divergence by design — that behavior is intentional, not a bug
- DMRfinder clusters CpG sites but cannot model sets of regions, quantitative traits, or batch effects, so downstream behavioral equivalence is not established by this output diff alone

- [methods] Clustering is not biased because it uses only site locations: "it does not consider methylation levels, and thus is not biased in favor of (or opposed to) finding DMRs"
- [methods] Chaining effect limited by splitting long regions: "The DMRfinder script limits this effect by splitting any region whose length exceeds a specified threshold (by default, 500 bp)"
- [methods] combine_CpG_sites.py role in pipeline: "The DMRfinder script `combine_CpG_sites.py` takes one or more samples' methylation counts at individual CpG sites and produces a single output"
