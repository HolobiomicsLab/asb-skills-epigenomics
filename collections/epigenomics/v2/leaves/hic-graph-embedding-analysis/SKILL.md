# hic-graph-embedding-analysis

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Clusters 16-dimensional graph auto-encoder (GAE) embeddings of Hi-C genomic bins with unsupervised HDBSCAN to assign one label per bin, forming the clustering module of the TOAST TAD-identification pipeline.

## When to use

Use when you have low-dimensional node embeddings (e.g., 16-dim GAE output from 400x400 Hi-C submatrices) and must assign a density-based cluster label to every genomic bin without specifying the number of clusters.

## When NOT to use

- Input is a raw NxN Hi-C contact matrix rather than trained GAE embeddings — clustering should operate on the embedding, not the contact matrix directly
- The number of clusters must be fixed a priori or labels must be generated by a supervised model — HDBSCAN here is run in unsupervised mode with automatic cluster discovery

## Inputs

- 16-dimensional GAE node embedding matrix Z per 400x400 Hi-C submatrix (numpy/pandas-loadable)
- Chromosome/submatrix identifiers and genomic bin indices for each row of Z

## Outputs

- bin_labels.csv with exactly one cluster label per genomic bin (bin index, chromosome/submatrix identifier, cluster label)
- Noise-flagged bins (low-density points labeled as outliers by HDBSCAN)

## How to apply

Load the 16-dimensional node embedding matrix Z output by the trained GAE encoder (TOAST uses a 2-layer GAE with hidden dimension 64 and embedding dimension 16, trained on non-overlapping 400x400 Hi-C submatrices). Run the hdbscan package's HDBSCAN algorithm in unsupervised mode on Z, letting it automatically discover clusters of varying densities and flag low-density bins as noise rather than forcing a fixed k. Collect one cluster label per genomic bin (bin index, chromosome/submatrix identifier, label) and write bin_labels.csv with pandas, one row per bin. Rationale: HDBSCAN's hierarchical cluster extraction assigns labels to every bin of the embedding, which downstream TOAST steps convert into TADs by merging contiguous same-label regions (contiguous regions longer than 200 Kb are identified as TADs).

## Related tools

- **TOAST** (Pipeline whose clustering module coordinates the generated GAE embeddings and labels each bin via HDBSCAN) — https://github.com/ghaiyan/TOAST
- **hdbscan** (Unsupervised HDBSCAN clustering of the 16-dimensional embeddings to assign one label per genomic bin)
- **numpy** (Loads and passes the embedding matrix Z into HDBSCAN)
- **pandas** (Collects bin labels and writes bin_labels.csv with one row per bin)

## Examples

```
import hdbscan, pandas as pd; labels = hdbscan.HDBSCAN().fit_predict(Z); pd.DataFrame({'bin': range(len(labels)), 'label': labels}).to_csv('bin_labels.csv', index=False)
```

## Evaluation signals

- bin_labels.csv exists, is parseable, and contains exactly one label per genomic bin of each 400x400 submatrix
- Cluster labels are produced without a preset number of clusters (unsupervised mode), with low-density points optionally flagged as noise
- Downstream: contiguous genomic regions sharing the same label merge into TADs, and only contiguous regions exceeding 200 Kb are kept as TADs
- Label count and bin count match the 16-dimensional embedding matrix Z rows (hidden_dim=64, output_dim=16 configuration)

## Limitations

- Low-density bins may be flagged as noise and left without a meaningful cluster label, leaving gaps between TAD calls
- Labeling quality depends on the upstream GAE configuration; the paper found the optimal result with a 2-layer network, embedding dimension 16, hidden layer dimension 64
- HDBSCAN in unsupervised mode gives no control over the exact number of clusters per submatrix
