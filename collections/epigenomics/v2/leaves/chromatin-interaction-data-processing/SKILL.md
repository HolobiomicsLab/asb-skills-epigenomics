# chromatin-interaction-data-processing

## Summary

Run ChIA-PIPE, a fully automated pipeline that performs linker filtering, read mapping, peak calling, loop calling, and automated quality control on ChIA-PET data, and extend it via pseudolinker handling to related 3D genome assays (HiChIP, PLAC-seq), producing peak/loop calls plus browser-ready .hic and .cool contact maps.

## When to use

Use when raw paired-end FASTQ from ChIA-PET, HiChIP, or PLAC-seq libraries must be processed end-to-end into peaks, loops, chromatin contact domains, and 2D contact maps viewable in Juicebox/HiGlass.

## When NOT to use

- Input is already processed interaction data (e.g., existing peak/loop BED files or .hic/.cool maps) rather than raw paired-end FASTQ needing linker filtering and alignment.
- The assay is a standard Hi-C library with no bridge linker, since ChIA-PIPE's linker filtering and pseudolinker handling target ChIA-PET/HiChIP/PLAC-seq junction structure.

## Inputs

- Paired-end ChIA-PET FASTQ files (e.g., LDK0004-ds_*.fastq.gz test data)
- HiChIP or PLAC-seq FASTQ libraries (via pseudolinker handling)
- Pipeline configuration file (e.g., chia_pipe-master/example_config_file.sh)
- Reference genome for BWA-ALN/BWA-MEM alignment

## Outputs

- Peak calls and loop calls (loops with PET count >= 3 and peak support)
- Chromatin contact domains (genomic regions of at least 25 kb with continuous loop coverage)
- .hic and .cool files for Juicebox and HiGlass 2D contact map viewing
- Automated quality control assessment per dataset
- Allele-specific peak/loop resolutions and enhancer-promoter loop annotations

## How to apply

Clone ChIA-PIPE from github.com/TheJacksonLaboratory/ChIA-PIPE into a working directory and install all dependencies locally with local_install_chia_pipe_dependencies.sh into a dedicated dependency directory. Place raw FASTQ (e.g., the LDK0004-ds test files) in a fastq/ subdirectory, then launch the full workflow via 0.chia_pipe_shell.sh with example_config_file.sh, or on an HPC cluster by submitting 0.chia_pipe_hpc.pbs via qsub with the --conf flag. The pipeline categorizes read pairs for genuine bridge linker sequence between the two genomic tags during linker filtering, maps flanking sequences to the reference genome with a hybrid of BWA-ALN and BWA-MEM, and supports short-read (2 x 21 bp) or long-read (2 x 150 bp) data. HiChIP and PLAC-seq libraries, despite different junction sequences between the two tags, are processed through pseudolinker handling within the same run. Post-alignment, retain only unique alignments with MAPQ >= 30 and nonredundant PETs via the CPU dedup module; classify PETs with genomic span <= 8 kb as self-ligation and use only linker-detected, both-end-genomic PETs for loop detection. Finally, generate .hic and .cool files so 2D contact maps render immediately in Juicebox and HiGlass, and inspect peaks/loops in the BASIC Browser.

## Evaluation signals

- Pipeline completes on the LDK0004-ds test FASTQ dataset without errors.
- Browser-ready .hic and .cool contact map files are produced and render in Juicebox and HiGlass.
- Peak and loop call outputs are present, with loops meeting PET count >= 3 and peak-support criteria.
- Retained alignments are unique (MAPQ >= 30) and nonredundant after CPU dedup.
- 2D heat maps from ChIA-PET, HiChIP, and PLAC-seq outputs show qualitatively comparable chromatin interactions in the BASIC Browser.

## Limitations

- No numeric QC threshold is reported for accepting a run; acceptance is the qualitative presence of complete, viewable .hic/.cool and peak/loop outputs.
- The reference genome version used for BWA-ALN/BWA-MEM alignment is not specified in the article's discussion section.
- Older pipelines performing peak calling on very large datasets without an input-control sample produce an abundance of false-positive peaks; ChIA-PIPE defaults to input-control peak calling with stringent settings to avoid this.
