# weighted-average-ensemble-fusion

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Fuses the outputs of a random forest (RF.py) base model and a CNN (CNN.py) base model into a single promoter predictor via a weighted average algorithm (Weighted_average.py), as implemented in iPro-WAEL for promoter identification across seven species.

## When to use

Use when two complementary base classifiers (e.g. RF and CNN) trained on the same promoter/non-promoter sequences must be combined into one ensemble prediction without retraining, following the iPro-WAEL weighted average design.

## When NOT to use

- Only one base model is available (e.g. you already have a standalone RF or CNN prediction) — the weighted average requires both RF and CNN outputs to fuse
- Sequences are not yet featurized — run feature_code.py for word2vec features and iLearnPlus for the other features before invoking the ensemble
- The goal is motif/TFBS interpretation rather than promoter prediction — use feature_importance.rar instead

## Inputs

- Labeled promoter/non-promoter training and independent test sequences from the 'EPdata' folder (first half of each file labeled 1, second half labeled 0)
- word2vec-based feature file generated by feature_code.py using index_promoters.txt and word2vec_promoters.txt benchmark files for human
- Additional sequence features extracted with iLearnPlus
- Trained random forest base model (RF.py) and CNN base model (CNN.py) outputs

## Outputs

- Fused weighted-average ensemble promoter/non-promoter predictions per sequence
- Per-cell-line performance metrics (sensitivity, specificity, accuracy, MCC) recorded in cv_results.csv
- Cross-cell line prediction performance metrics compiled into cross_cell_line_results.csv

## How to apply

First train the random forest base model with RF.py and the CNN base model with CNN.py (keras 2.3.1 on tensorflow 2.0.0, Python 3.6) on the labeled sequences in the EPdata folder, where the first half of each file is labeled 1 and the second half is labeled 0. Prior to training, extract word2vec-based features by running `python feature_code.py` (with index_promoters.txt and word2vec_promoters.txt as human benchmark files) and extract remaining features with iLearnPlus. Then run `python main.py`, which imports RF, CNN and Weighted_average, so the weighted average algorithm (Weighted_average.py) fuses the two base models' outputs into the final ensemble prediction. Manually modify the 'cell_lines' variable in main.py to switch the predicted cell line (e.g. GM12878, K562, HeLa-S3, HUVEC) — this is also how cross-cell line prediction is performed, by letting a model trained on one cell line predict the independent test sets of the other three. Validate by ten-fold cross-validation per cell line, recording sensitivity, specificity, accuracy and MCC, and compare against same-cell line and prior-method (Z-curve) baselines.


## Evaluation signals

- Reproduced per-cell-line ten-fold cross-validation metrics (sensitivity, specificity, accuracy, MCC) match the extremely high performance values reported in Supplementary Table S5 within a small tolerance
- Cross-cell line predictions outperform Z-curve, the best-performing previous method on human datasets, and are not significantly different from same-cell line performance
- main.py runs to completion importing RF, CNN and Weighted_average without import or dependency errors under Python 3.6 / keras 2.3.1 / tensorflow 2.0.0
- Predictions respect the EPdata labeling convention (first half of each file labeled 1, second half labeled 0) when computing confusion-matrix-based metrics
- Switching the 'cell_lines' variable in main.py changes the predicted cell line as intended for all four human cell lines (GM12878, K562, HeLa-S3, HUVEC)

## Limitations

- The variable 'cell_lines' in main.py must be manually modified to change the predicted cell line; there is no CLI flag or config file for this
- The feature file for the human dataset is too large to upload to GitHub and must be regenerated with feature_code.py; only R.capsulatus.rar is provided as an example feature file to verify model performance
- Versions are not specified for sklearn, numpy, and h5py (unlike Python 3.6, keras 2.3.1, tensorflow 2.0.0); see requirements.txt for all detailed libraries
