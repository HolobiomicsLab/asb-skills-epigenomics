# atac-dnase-technology-benchmarking

## Summary

Benchmark open-chromatin peak sets from ATAC-seq and DNase-seq by intersecting each with K562 ChromHMM chromatin-state annotations in EpiCompare, tabulating per-state peak overlap percentages and rendering a comparative ChromHMM heatmap to expose technology-specific annotation differences.

## When to use

Use when contrasting open-chromatin peak files generated by different technologies (e.g. K562 ATAC-seq vs DNase-seq narrowPeak files from ENCODE) and you need ChromHMM-based annotation differences as the benchmarking readout.

## When NOT to use

- Input is raw sequencing data (FASTQ) or reads rather than already-called narrowPeak/BED peak files — EpiCompare operates on peak files, not alignment or peak calling
- Only a single peak file with no comparison set exists — benchmarking requires contrasting multiple epigenomic peak sets
- The goal is de novo chromatin-state discovery (training a ChromHMM model) rather than intersecting peaks with a prebuilt cell-line ChromHMM annotation

## Inputs

- narrowPeak/BED peak files for each technology (e.g. K562 ATAC-seq and K562 DNase-seq, ENCODE accession ENCFF044JNJ)
- K562 chromHMM annotation cell-line (chromatin-state segment file)
- genome build specification per peakfile and reference (hg19/hg38, e.g. ENCODE blacklist regions for hg19 and hg38)
- optional Picard summary output txt files for duplication-rate metrics

## Outputs

- single interactive HTML EpiCompare report collating all results
- ChromHMM annotation heatmap comparing chromatin-state distribution across the peak files (paper Fig. 1d)
- tabulated percentage of peaks overlapping each ChromHMM state per peak set
- general metrics (percentage of blacklisted and non-standard peaks, peak widths, duplication rate) and peak-overlap statistics

## How to apply

Load each narrowPeak/BED peak file (e.g. K562 ATAC-seq and K562 DNase-seq ENCODE accession ENCFF044JNJ) into R and standardize them as GRanges objects via EpiCompare; peaks in ENCODE blacklisted regions and on non-standard chromosomes are removed first, so per-state percentages are computed on retained peaks only. Supply the K562 chromHMM annotation cell-line so EpiCompare intersects each peak set with the chromatin-state segments and tabulates the percentage of peaks overlapping each state. Run EpiCompare with a matched genome_build (hg19/hg38 per input and output build) so the ChromHMM annotation heatmap renders both peak files side by side in the single interactive HTML report. Finally, contrast the per-state overlap percentages between the ATAC-seq and DNase-seq peak sets — a differential chromatin-state distribution (as in Fig. 1d of the paper) is the expected benchmarking signal.

## Related tools

- **EpiCompare** (primary package: standardizes peak files as GRanges, removes blacklisted/non-standard peaks, intersects peaks with chromHMM states, plots the ChromHMM heatmap, and outputs the HTML report) — https://github.com/neurogenomics/EpiCompare
- **ChromHMM** (source of the K562 cell-line chromatin-state annotation that each peak set is intersected with for per-state overlap tabulation)
- **R** (runtime environment; EpiCompare is a Bioconductor (>= v3.15) R package run in R/RMarkdown sessions)

## Examples

```
EpiCompare::EpiCompare(peakfiles = list(ATAC = atac_k562, DNase = dnase_k562), genome_build = list(peakfiles = "hg19", reference = "hg38"), genome_build_output = "hg19", output_dir = tempdir())
```

## Evaluation signals

- Blacklisted-region and non-standard-chromosome peaks are removed from every peak file before analysis, so per-state percentages are computed on retained peaks only
- The output is a single interactive HTML report containing the three sections: General Metrics, Peak Overlap, and Functional Annotation (ChromHMM, ChIPseeker, TSS enrichment)
- The tabulated per-state overlap percentages differ between the ATAC-seq and DNase-seq peak sets, matching the differential ChromHMM annotation observed in Fig. 1d
- The chromHMM heatmap renders both peak files against the K562 annotation with a consistent genome build (e.g. all inputs lifted to hg19 via genome_build_output)
- Reproducible reports can be cross-checked against the EpiArchives atac_dnase_example report and its published reproduction code

## Limitations

- Peaks in ENCODE blacklisted regions and on non-standard chromosomes are excluded prior to analysis, so state percentages describe only the retained subset
- Documentation, available functions, and parameters differ between EpiCompare versions — the GitHub README covers the development version, older Bioconductor releases may behave differently
- ChromHMM annotation results depend on the supplied cell-line annotation (K562 here) and are therefore cell-type-specific
