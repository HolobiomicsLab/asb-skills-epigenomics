# samtools-bam-filtering

## Summary

Filter aligned ChIPseq/RNAseq BAM files with SAMtools according to user-specified NEAT parameters (duplicate-read management policy, minimum and maximum fragment sizes), as implemented in NEAT's 'filter' module that runs after 'map' and before 'peakcalling'.

## When to use

Use when aligned BAM files from a mapped ChIPseq/RNAseq run must be filtered by fragment-size bounds and duplicate-read policy before peakcalling or downstream normalization.

## When NOT to use

- Input is still raw FASTQ or has not been mapped — the NEAT pipeline runs 'unzip', 'rename', 'QC' and 'map' before 'filter'
- The goal is adapter or quality trimming of reads rather than fragment-size and duplicate filtering of aligned reads (that belongs to the 'QC' module)
- The task is peak calling itself or reorganizing/storing .bam and .bai files — use NEAT's 'peakcalling' or 'cleanfiles' modules instead

## Inputs

- Aligned BAM file produced by the NEAT 'map' module (bwa or bowtie mappings)
- User-defined filtering parameters from AdvancedSettings.txt: duplicate-read management policy and minimum/maximum fragment sizes

## Outputs

- Filtered, sorted .bam file (sorted with samtools sort)
- Companion .bai index file (samtools index)

## How to apply

Read the user-configured parameters from the centralized AdvancedSettings.txt file, which in NEAT stores alignment-, filtering- and peak calling parameters together with sample names, replicates, conditions and antibodies. First use 'samtools view' to retain only alignments whose fragments fall within the configured minimum and maximum fragment sizes. Then apply 'samtools rmdup' according to the duplicate-read management policy the user specified (removing or marking duplicate reads). Finish by sorting the filtered alignments with 'samtools sort' and generating the .bai companion with 'samtools index' so the file is queryable downstream. Validation confirms the output exists, parses as a valid BAM, and is accompanied by its .bai index before NEAT's 'peakcalling' or 'cleanfiles' modules consume it.

## Related tools

- **SAMtools** (Executes the filtering: samtools view applies fragment-size boundaries, samtools rmdup manages duplicate reads, samtools sort orders alignments, samtools index builds the .bai index)
- **NEAT** (Pipeline framework whose 'filter' module wraps the SAMtools steps and supplies user parameters from the centralized AdvancedSettings.txt file) — https://github.com/pschorderet/NEAT

## Examples

```
samtools view -b aligned.bam | samtools rmdup - filtered.bam; samtools sort filtered.bam -o filtered.sorted.bam; samtools index filtered.sorted.bam
```

## Evaluation signals

- The filtered .bam output file exists in the project folder after the module completes
- The output parses as a valid BAM file (e.g., loads without error in a BAM reader)
- A .bai index generated by samtools index accompanies the filtered BAM
- All retained alignments fall within the minimum and maximum fragment sizes configured in AdvancedSettings.txt
- Duplicate reads are handled according to the user-specified duplicate-read management policy (e.g., absent after samtools rmdup)

## Limitations

- NEAT was still under development per the README, with bugs to be reported by users; the article gives no NEAT version number or changelog
- The article states the operating system is limited to Mac OSx, with no Linux/Windows support stated
- The article presents no concrete quantitative results for this pipeline stage — tangible results are in the form of outputs (Fig. 3)
- Downstream, .bam and .bai files must be reorganized by the 'cleanfiles' module before downstream analysis, so raw filtered output is not the final stored form
