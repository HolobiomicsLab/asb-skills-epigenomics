# delila-book-regeneration-from-filtered-sequences

## Summary

In Delila-PY's second cycle, per-sequence information content values (bits, from alist/encode/cmp/rseq) are used by the ri program to drop poorly matching sequences (≤0 bits), and the retained sequences are written to a new file and fed back to delila to regenerate an updated book of sequences.

## When to use

Use when running the Delila-PY pipeline's second cycle and you have per-sequence information content values in bits that must be filtered with the ri program's ≤0-bit cutoff before regenerating the delila book.

## When NOT to use

- You are in cycle 1 (malign/malin alignment search), which does not apply the ri ≤0-bit filter
- You are generating the final DNA motif (cycle 3: alist, encode, cmp, rseq, dalvec, makelogo) rather than refining the input set
- All sequences have positive information content and no filtering is needed (ri removes nothing)

## Inputs

- Per-sequence information content values in bits from the cycle-2 alist/encode/cmp/rseq computation
- Delila library files generated by dbbk and catal
- Current delila book/sequence list

## Outputs

- Filtered sequence list file containing only sequences with information content >0 bits
- Updated book file regenerated by delila from the filtered sequence list

## How to apply

Load the per-sequence information content values (bits) produced by the alist/encode/cmp/rseq computation of cycle 2 into a table. Apply the ri program rule deterministically: retain a sequence only if its information content is >0 bits, and mark it for removal if it is ≤0 bits. Write the retained sequences to a filtered sequence list file, which is then fed back to the delila program together with the library files to generate an updated book of sequences. This step mirrors the article's cycle 2 description: poorly matching sequences (≤0 information content, ri program) are removed and a new file is generated and fed back to delila. Validate by independently recounting retained/removed sequences with the ≤0-bit cutoff and confirming no retained sequence has information content ≤0 bits.

## Related tools

- **ri** (Applies the deterministic ≤0-bit information content cutoff to remove poorly matching sequences)
- **delila** (Regenerates an updated book of sequences from the filtered sequence list and library files)
- **Delila-PY** (Pipeline (written in Python3) that orchestrates the cycle-2 filtering and book regeneration) — github.com/GLBRC/delila
- **Python3** (Implementation language of the delila_pipeline.py driver that runs the cycle) — github.com/GLBRC/delila
- **rseq** (Produces the per-sequence information content values that feed the ≤0-bit filtering rule)

## Examples

```
delila_pipeline.py -g Rsphaeroides_GenBank.gbff -l -10 -r -10 -s Location_File_Example.txt -t "Logo Title"
```

## Evaluation signals

- Number of retained + number of removed sequences exactly equals the count obtained by independently applying the ≤0-bit cutoff to the input information-content table
- No sequence in the filtered (retained) list has information content ≤0 bits
- Every removed sequence has information content exactly ≤0 bits (0 or negative)
- delila completes successfully and produces an updated book file from the filtered sequence list and library files

## Limitations

- The cutoff is fixed at ≤0 bits by the ri program's rule in Delila-PY; no user-adjustable threshold is described in the article
- Tested on MacOS and Linux (Ubuntu and CentOS); other operating systems may require additional work per the README
