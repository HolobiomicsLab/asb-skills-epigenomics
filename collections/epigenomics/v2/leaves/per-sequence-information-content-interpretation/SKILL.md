# per-sequence-information-content-interpretation

## Summary

In Delila-PY's second cycle, per-sequence information content (in bits) is computed by the alist/encode/cmp/rseq chain, and the ri program applies a deterministic ≤0-bit cutoff to discard poorly matching sequences before delila regenerates the book. This interprets each sequence's individual information contribution as a quality score for motif refinement.

## When to use

Use when a cycle-2 Delila-PY run has produced per-sequence information content values (bits) and you must decide which sequences are poor matches to keep or drop before regenerating the book with delila.

## When NOT to use

- The input is the raw book from cycle 1 — per-sequence information content has not yet been computed by alist/encode/cmp/rseq, so the ≤0-bit cutoff cannot be applied.
- The goal is motif/logo rendering (cycle 3: alist, encode, cmp, rseq, dalvec, makelogo) rather than filtering sequences out of the book.
- You need soft or probabilistic down-weighting of poor matches; the ri rule is strictly binary at the ≤0-bit boundary and offers no graded removal.

## Inputs

- Per-sequence information content table (bits) from the cycle-2 alist/encode/cmp/rseq computation
- Sequence list of cycle-2 sites
- Delila library files (generated by dbbk and catal from the GenBank file)

## Outputs

- Filtered sequence list file containing only sequences with information content >0 bits
- Updated book file regenerated by delila from the filtered sequence list
- Counts of retained (>0 bits) and removed (≤0 bits) sequences

## How to apply

Load the per-sequence information content values (bits) produced by the alist, encode, cmp, and rseq programs in cycle 2 into a table. Apply the ri program rule deterministically: retain a sequence if its information content is >0 bits, remove it if it is ≤0 bits. Write the retained sequences to a filtered sequence list file and feed it back to delila together with the library files to generate an updated book file. The rationale is that sequences contributing zero or negative information are poor matches to the emerging motif and would dilute the final logo generated in cycle 3. Validate by independently applying the ≤0-bit cutoff and confirming retained+removed counts and that no retained sequence has information ≤0 bits.

## Evaluation signals

- Number of retained sequences plus number of removed sequences exactly equals the count obtained by independently applying the ≤0-bit cutoff to the input information-content table.
- No sequence in the filtered list has information content ≤0 bits.
- Every removed sequence has information content ≤0 bits under the rseq-derived values.
- delila successfully regenerates a book file from the filtered sequence list without errors, and the book contains only retained sequences.
- The cycle-3 logo (makelogo) is built from the updated book, confirming the filter preceded motif generation.

## Limitations

- The cutoff is fixed at ≤0 bits of information content; the article does not describe user-tunable thresholds.
- The rule depends on the quality of the cycle-1 malign/malin alignment — a poor initial alignment can mislabel sequences before any filtering occurs.
- Sequences exactly at 0 bits are removed, so borderline weak-but-positive contributors near 0 may behave inconsistently with small numeric changes.
