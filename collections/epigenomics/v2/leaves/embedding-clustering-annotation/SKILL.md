# embedding-clustering-annotation

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Assigns a cluster label to each genomic bin by running the unsupervised HDBSCAN algorithm on 16-dimensional GAE embeddings derived from 400x400 Hi-C submatrices, as done in TOAST; contiguous regions sharing a label become TADs.

## When to use

Use when you already have low-dimensional node embeddings (e.g., 16-dim GAE output per 400x400 Hi-C submatrix) and need density-based, parameter-light unsupervised clustering to label every bin.

## When NOT to use

- Input is still a raw NxN Hi-C contact matrix — embeddings must be generated by the GAE module first (train with hidden_dim=64, output_dim=16 on non-overlapping 400x400 submatrices)
- You need multiscale or parameter-tunable TAD boundaries — HDBSCAN runs unsupervised with no user-set metric parameters, unlike Armatus/TopDom-style callers
- Embedding dimension differs substantially from the validated 16-dim (or 128-dim single-layer) setting, where the paper's TAD identification quality was established

## Inputs

- 16-dimensional node embedding matrix Z per 400x400 Hi-C submatrix (output of trained GAE encoder, loaded via pandas/numpy)
- Submatrix/bin identifiers (bin index, chromosome/submatrix identifier)

## Outputs

- bin_labels.csv with one row per genomic bin: bin index, chromosome/submatrix identifier, cluster label (noise bins flagged by HDBSCAN)
- Per-bin labels feeding contiguous-region TAD identification

## How to apply

Load the 16-dimensional node embedding matrix Z output by the trained GAE encoder for each 400x400 Hi-C submatrix using pandas/numpy. Run the hdbscan package's HDBSCAN in unsupervised mode on Z so the algorithm automatically discovers clusters of varying densities as a hierarchical tree, letting it flag low-density points as noise via its built-in condensed-hierarchy pruning. Collect one label per bin (bin index, chromosome/submatrix identifier, cluster label) into bin_labels.csv with one row per bin. TOAST's TAD generation module then treats contiguous genomic regions with the same label as candidate TADs, keeping only regions longer than 200 Kb. Rationale: the paper found optimal embeddings with a 2-layer GAE (hidden_dim=64, output_dim=16), and HDBSCAN avoids the complex parameter settings of prior TAD callers like Armatus, Arrowhead, TopDom, and TADbit.

## Related tools

- **HDBSCAN** (Unsupervised density-based clustering algorithm that assigns a label to each genomic bin from the GAE embeddings; flags low-density points as noise)
- **hdbscan** (Python package implementing HDBSCAN, installed via pip in the TOAST environment)
- **TOAST** (Pipeline whose clustering module coordinates the generated embeddings and labels each bin before TAD generation) — https://github.com/ghaiyan/TOAST
- **numpy** (Loads and manipulates the 16-dimensional embedding matrices prior to clustering)
- **pandas** (Writes one cluster label per genomic bin to bin_labels.csv)

## Examples

```
import pandas as pd, numpy as np, hdbscan; Z = pd.read_csv('embeddings.csv').values; labels = hdbscan.HDBSCAN().fit_predict(Z); pd.DataFrame({'bin': range(len(labels)), 'label': labels}).to_csv('bin_labels.csv', index=False)
```

## Evaluation signals

- bin_labels.csv exists, is parseable with pandas, and contains exactly one label per genomic bin of each 400x400 submatrix
- HDBSCAN was run in unsupervised mode (no user-supplied cluster-count or metric parameters) on the full 16-dimensional embedding matrix
- Embeddings derive from the validated GAE configuration: 2-layer network, hidden_dim=64, output_dim=16
- Downstream TAD check: contiguous same-label regions exceeding 200 Kb are recovered as TADs
- On simulated data (Wang et al.), expect FMS around 0.98 versus ground-truth TADs; TAD count difference of 1-8 and average-length difference up to 5 Kb

## Limitations

- Low-density embedding points are flagged as noise by HDBSCAN's built-in pruning and receive no cluster label
- Optimal TAD identification was only validated for hidden_dim=64/output_dim=16 (or a single-layer network with output_dim=128); other embedding dimensions were less robust
- Only contiguous regions longer than 200 Kb qualify as TADs, so shorter labeled segments are discarded
