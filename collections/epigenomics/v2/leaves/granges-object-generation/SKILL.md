# granges-object-generation

## Summary

NEAT's 'GRanges' module converts processed .bam/.bai alignments into compact R/Bioconductor GRanges objects (~40–60 Mb, versus ~4–6 Gb for bam) that are the prerequisite input for NEAT's downstream exploratory analyses such as metagene and differentially expressed gene analysis.

## When to use

Use when a ChIPseq or RNAseq pipeline stage must hand off filtered bam alignments into R/Bioconductor for metagenomic or DEG analysis, and bam files are too large to manipulate or share.

## When NOT to use

- The goal is genome-browser visualization tracks (wig or bigwig) — use NEAT's Wig and Bigwig modules instead, which also operate on the filtered alignments.
- The analysis is not performed in R/Bioconductor and GRanges objects cannot be consumed downstream.
- Input alignments have not passed the NEAT 'filter' module (duplicate read handling and fragment size limits not yet applied).

## Inputs

- Filtered .bam/.bai alignment files (output of NEAT 'filter' module using samtools)
- NEAT project settings file AdvancedSettings.txt with sample names, replicates, conditions, antibodies and filtering/peakcalling parameters

## Outputs

- R/Bioconductor GRanges objects (~40–60 Mb, significantly smaller than the input bam files)
- Files stored and archived in the NEAT project folder for downstream analysis

## How to apply

Run this module after NEAT's 'filter' step, which uses samtools to manage duplicate reads and fragment size limits and produces the filtered .bam/.bai for the truncated H3K4me3 ChIPseq or RNAseq test dataset. The module reads those alignments and converts them into GRanges objects in R, using the Bioconductor infrastructure NEAT relies on. The rationale is size reduction and portability: GRanges objects are orders of magnitude smaller than bam files, matching NEAT's goal that small-sized files can be consolidated and shared across users and institutions. The resulting GRanges objects are explicitly stated to be 'necessary for downstream analysis', i.e. they feed metagene analysis for ChIPseq and differential expression analysis for RNAseq rather than the wig/bigwig browser-track outputs, which are generated by the separate Wig and Bigwig modules. Validate by checking the object size falls near the ~40–60 Mb range reported for GRanges versus ~4–6 Gb for bam.

## Evaluation signals

- Output GRanges objects should fall near the ~40–60 Mb size range reported in the paper, versus ~4–6 Gb for the source bam files.
- Objects must be loadable as GRanges in R/Bioconductor and usable by NEAT's downstream analysis modules.
- One GRanges object per filtered sample should be present and consistent with the sample list in the centralized settings file (sample names, replicates, conditions).
- Module should run as part of the automated pipeline without manual file manipulation between filter and analysis steps.

## Limitations

- NEAT only supports Mac OSx; no Linux/Windows support is stated.
- NEAT is still under development (README notes 'NEAT is still under developent. If you encounter any bug, please contact us.') and no changelog is provided.
- Paper reports no concrete quantitative results for this module beyond output file sizes (tangible results are in the form of outputs, Fig. 3).
