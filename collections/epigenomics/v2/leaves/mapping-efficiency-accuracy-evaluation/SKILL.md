# mapping-efficiency-accuracy-evaluation

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Benchmark workflow for comparing DNA methylation aligners (Msuite 3-/4-letter mode, Bismark, BWA-meth) on simulated TAPS-protocol reads by computing mapping efficiency, mapping accuracy, running time, and peak memory usage.

## When to use

Use when aligner performance on bisulfite or bisulfite-free (TAPS) methylation reads must be quantified and compared in speed, memory, mapping efficiency, and accuracy.

## When NOT to use

- Input data is generated with a BS-seq protocol — 4-letter mode only supports TAPS/5hmC-CATCH data; BS-seq requires 3-letter mode with -m BS
- The goal is methylation calling quality or TSS-level methylation profiling rather than aligner benchmarking
- Reads are not from a DNA methylation assay (e.g., standard WGS or RNA-seq), where Bismark/BWA-meth/Msuite-style bisulfite-aware alignment is inappropriate

## Inputs

- Simulated paired-end 100-bp and 36-bp FASTQ read pairs (1 million pairs) generated by SHERMAN with TAPS-protocol settings
- Reference genome FASTA (e.g., GRCh38) plus RefSeq annotation for index building
- Optionally a real TAPS/BS FASTQ dataset from GEO (e.g., GSE112520, GSE129673)

## Outputs

- Aggregated benchmark table (e.g., table2_benchmark.tsv) with one row per tool/mode and columns for read length, mapping efficiency (%), accuracy (%), running time, and peak memory
- SAM/BAM alignment files per tool, converted with samtools
- Alignment logs with time and memory profiling measurements

## How to apply

Generate in-silico paired-end 100-bp and 36-bp TAPS-protocol reads (1 million read pairs) with the SHERMAN script using 20% C-to-T conversion at CpG sites, 0.5% at CpH sites, 0.1% sequencing error rate, and reads restricted to CT/GA-rich regions (CT or GA proportion >=80%). Build genome indices with Msuite's build.index.sh utility from the reference FASTA plus RefSeq annotation, then run Msuite in 3-letter mode (-3 -m TAPS) and 4-letter mode (-4 -m TAPS) by launching the generated makefile in the output directory; run Bismark v0.22.3 and BWA-meth v0.2.2 with default settings on the same read sets for 3-letter comparison. Measure total running time and peak memory with standard system profiling (e.g., /usr/bin/time), including Msuite's adapter- and quality-trimming step in its time. Aggregate mapping efficiency (%), accuracy (%), time, and peak memory into a table with one row per tool/mode; judge success by reproducing the published mapping efficiencies (Msuite 3-letter 96.19%, 4-letter 95.75%, Bismark 95.79%, BWA-meth 95.58% on 100-bp reads, within rounding tolerance) and confirming Msuite is faster with lower memory than Bismark despite the extra trimming step.

## Examples

```
msuite -x hg38 -1 reads_R1.fq -2 reads_R2.fq -3 -m TAPS -o out.dir
```

## Evaluation signals

- Mapping-efficiency values on 100-bp reads reproduce Table 2: Msuite 3-letter 96.19%, Msuite 4-letter 95.75%, Bismark 95.79%, BWA-meth 95.58% (within rounding tolerance)
- Msuite's total time (including its adapter-/quality-trimming step) is lower than both Bismark and BWA-meth on the same read sets
- Msuite's peak memory usage (/usr/bin/time) is lower than Bismark's for identical input
- Benchmark table has exactly one row per tool/mode with populated read-length, efficiency, accuracy, time, and memory columns
- Simulated reads are restricted to CT/GA-rich regions with CT or GA proportion >=80% and reproduce the specified conversion rates (20% CpG, 0.5% CpH, 0.1% error)

## Limitations

- No strong evidence that 4-letter mode is more accurate on inconsistent CpG sites; further validation needed
- Accuracy of 4- and 3-letter modes and limitations of current sequencing-based protocols require validation with additional methods such as microarrays
- On real TAPS data, chemical treatment was imperfect, so simulated-benchmark accuracy figures may not transfer exactly to real datasets
