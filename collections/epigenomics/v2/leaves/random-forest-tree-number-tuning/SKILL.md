# random-forest-tree-number-tuning

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Grid-search optimization of the random forest tree count (n_estimators) for the iPro-WAEL promoter-prediction RF component, as demonstrated on the GM12878 cell line where 300 trees was identified as the best configuration.

## When to use

Use when building the RF component of an iPro-WAEL-style promoter classifier and you need to empirically select the number of trees via cross-validated grid search over promoter training sequences.

## When NOT to use

- Input is already a set of trained iPro-WAEL component models with fixed hyperparameters (the 'model' folder provides trained models for validation, not re-tuning)
- The goal is tuning the CNN component (learning rate, kernel number, kernel size) rather than the RF tree number
- Working with the enhancer-vs-promoter discrimination task or cross-cell-line evaluation where the goal is applying, not optimizing, the RF component

## Inputs

- Promoter training sequences for a cell line (e.g., GM12878) from the EPdata folder, first half labeled 1, second half labeled 0
- Extracted feature matrix generated by feature_code.py (word2vec-based features) and iLearnPlus
- Candidate grid of random forest tree numbers

## Outputs

- Cross-validated performance metrics for each candidate tree number
- Best RF tree-number configuration (300 trees on GM12878)
- grid_search_results.csv containing the full sweep results and selected optima

## How to apply

Load the promoter training sequences (e.g., the GM12878 cell line files in the EPdata folder, where the first half of each file is labeled 1 and the second half is labeled 0) and extract their features with feature_code.py (word2vec-based features) and iLearnPlus (other features). Train random forest models with RF.py over a grid of candidate tree numbers using scikit-learn, recording cross-validated performance for each candidate. Select the tree count with the best cross-validated metric and persist the full sweep to grid_search_results.csv. On GM12878 this procedure identified an RF model with 300 trees as best; that value was adopted for the RF component of the ensemble alongside the CNN optimum (learning rate 0.001, 32 kernels, kernel size 11).

## Related tools

- **iPro-WAEL** (Framework whose RF component (RF.py) is tuned via the tree-number grid search) — https://github.com/HaoWuLab-Bioinformatics/iPro-WAEL
- **sklearn** (Provides the RandomForestClassifier used to train RF models over the grid of tree numbers)
- **feature_code.py** (Extracts word2vec-based features of promoters that feed the RF models) — https://github.com/HaoWuLab-Bioinformatics/iPro-WAEL
- **iLearnPlus** (Extracts the additional sequence features used alongside word2vec features for RF training)

## Examples

```
from sklearn.ensemble import RandomForestClassifier; rf = RandomForestClassifier(n_estimators=300)
```

## Evaluation signals

- Reproduced RF optimum on GM12878 must match the reported value of 300 trees
- Cross-validated performance must be recorded for every candidate tree number, not only the winner
- Full sweep results and selected optima are written to grid_search_results.csv
- Features are derived from EPdata training sequences with correct 1/0 labeling (first half positive, second half negative)
- The selected RF configuration, together with the CNN optimum (learning rate 0.001, 32 kernels, kernel size 11), is adopted unchanged for both component models

## Limitations

- The grid search was demonstrated on the GM12878 cell line; optima for other cell lines or species may differ and require re-running the sweep
- The word2vec benchmark files (index_promoters.txt, word2vec_promoters.txt) are human-specific, and the feature file for the human dataset is too large to upload to GitHub
- sklearn, numpy, and h5py versions are not pinned in the repository dependencies (unlike Python 3.6, keras 2.3.1, tensorflow 2.0.0), so environment reproducibility is partial
