# chipseq-quality-control-pipeline-execution

## Summary

Execute the ChiLin command-line pipeline to run a 13-step quality control and analysis workflow (FastQC, bwa mapping, MACS2 peak calling, PBC, replicate consistency, FRiP, meta-region annotation) on ChIP-seq or DNase-seq FASTQ inputs, emitting per-sample QC JSON statistics and summary tables.

## When to use

Use when raw ChIP-seq or DNase-seq FASTQ files (treatment and control) must be quality-controlled and analyzed end-to-end, and per-sample QC metrics such as FRiP, PBC, and replicate correlation are the required outputs.

## When NOT to use

- The task is single-metric QC on existing BAM/peak files where a dedicated QC package (e.g. phantompeakqualtools, ChIPseeker) would suffice without running the full mapping-to-peak-calling pipeline
- Input data are not ChIP-seq or DNase-seq (e.g. RNA-seq or ATAC-seq), which ChiLin does not support
- A GUI/point-and-click workflow is required rather than a command-line batch pipeline (ChiLin is an integrated command line pipeline)

## Inputs

- Single-end or paired-end ChIP-seq/DNase-seq FASTQ files (treatment replicates and control)
- Per-dataset ChiLin configuration file generated by 'chilin gen' (species, FASTQ paths, narrow/broad peak type)
- Species-dependent reference data archives (genome index, chrom_len, DHS/blacklist, geneTable; e.g. hg19.tgz)
- batch.conf file listing per-dataset configs for batch processing

## Outputs

- Per-sample QC JSON statistics (id_fastqc., id_map., id_frag., id_pbc., id_frip., id_macs2., id_rep., etc.)
- BAM alignments from bwa/bowtie/star mapping and MACS2 peak calls for replicates and merged BAMs
- id_summary.txt and id_report.pdf QC report with FRiP scores, wiggle correlations, replicate peak overlaps, and motif calls
- Aggregated plain-text and tabular summary covering 17 QC metrics across three QC layers per sample/dataset

## How to apply

Generate a per-dataset config with 'chilin gen', filling the [basics] section (species, treatment/control FASTQ paths, narrow or broad peak type) and confirming species reference data (genome index, chrom_len, DHS/blacklist, geneTable) downloaded from the cistrome.org archives (hg19/hg38/mm9/mm10) and verified with md5sum -c. Launch a single run with 'chilin simple' or batch runs by listing configs in a batch.conf and calling 'chilin batch -b batch.conf'; bwa is the default mapper and MACS2 (2.1.0 in the README conda spec) the default peak caller, with merged-BAM peak calling (step 6) mandatory and FastQC (step 1) skippable. The pipeline subsamples BAMs (4M reads) for MACS2 fragment-size estimation and PBC, computes replicate peak overlap/wiggle correlation, FRiP scores per sample, and annotates merged peaks with bedAnnotate.py; optional PhastCons, regulatory potential, and MDSeqPos motif steps are skipped automatically when peak number is under 200. Parse the emitted per-sample QC JSON files (id_fastqc., id_map., id_frag., id_pbc., id_frip., id_macs2., id_rep.) and aggregate them with the qc_summary_table modules into a plain-text and tabular summary of the 17 QC metrics across three QC layers.

## Related tools

- **ChiLin** (The pipeline itself: orchestrates the 13-step QC/analysis workflow, 'chilin simple' and 'chilin batch' entry points, emits per-sample QC JSON and summary tables) — https://github.com/cfce/chilin
- **bwa** (Default read mapper (step 2, cannot be skipped) producing the BAM files required by all downstream QC steps) — https://github.com/lh3/bwa
- **FastQC** (Step 1 (optional): sequence quality evaluation, reads GC contents evaluation and library contamination)
- **MACS2** (Default peak caller: fragment-size estimation on 4M-read subsampled BAMs (step 3) and replicate/merged peak calling (steps 5-6)) — https://github.com/taoliu/MACS/
- **samtools** (BAM manipulation supporting subsampling and QC metric extraction in the pipeline)
- **bedtools** (Interval operations underlying FRiP calculation and bedAnnotate.py meta-region annotation (steps 7-8))
- **MDSeqPos** (Optional step 12 motif analysis; automatically skipped when peak number is under 200) — https://bitbucket.org/cistrome/cistrome-applications-harvard

## Examples

```
chilin simple -u user -s hg19 --threads 8 -i id -o output -t treat1.fastq,treat2.fastq -c control1.fastq,control2.fastq -p narrow -r tf
```

## Evaluation signals

- Per-sample QC JSON files exist for each expected prefix (id_fastqc., id_map., id_frag., id_pbc., id_frip., id_macs2., id_rep.)
- Aggregated summary table contains the 17 QC metrics across three QC layers for every sample; the historical atlas validation matched Additional file 2: Table S1 (23,677 samples from 11,265 datasets)
- Replicate-consistency metrics fall within published reference ranges, e.g. H3K27me3 FRiP 0.04-0.32%, H3K4me3 wiggle correlation 0.02, TRRAP wiggle correlation 0.14 with 20-peak overlap
- Step 6 merged-BAM peak calling completed (it cannot be skipped) and produced peaks consumed by the bedAnnotate.py annotation step
- MDSeqPos motif step was correctly skipped for peak counts under 200 and otherwise produced motif calls (e.g. FOXA1/AR/CTCF in the case study)

## Limitations

- No software version is stated for ChiLin itself in the discussion; the only versioned pins appear in the README conda spec (bwa=0.7.13, samtools=0.1.19, bedtools=2.17.0, macs2=2.1.0, python 2)
- MDSeqPos motif analysis is automatically skipped when peak number is less than 200
- Steps 2 (mapping) and 6 (merged peak calling) cannot be skipped; the pipeline assumes command-line competence and installation of gcc, g++, java, R, python-dev dependencies
- ChiLin was designed for large batches (~100-1000s of datasets) with minimal user intervention; very small ad-hoc runs may not justify setup overhead
