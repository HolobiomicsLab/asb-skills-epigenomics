# computational-performance-reporting

## Summary

Benchmark and report the computational overhead of a workflow management system (Watchdog or Snakemake) by comparing total wall-clock execution time against the summed runtime of the actual executed tasks, demonstrating that WMS overhead is negligible relative to task runtime.

## When to use

Use when quantifying how much time a workflow management system itself adds on top of the real task runtimes, e.g. when validating that adopting a WMS does not inflate analysis wall time.

## When NOT to use

- The goal is to profile the runtime of the individual analysis tasks themselves rather than the overhead added by the workflow management system
- The workflows under test cannot be expressed identically in both Watchdog XML and Snakemake rules, so wall-time comparisons would not be attributable to the WMS
- Only a single sample count is available, so the trend of negligible overhead across the sample-count range cannot be assessed

## Inputs

- Watchdog workflow XML file (e.g. a configured example workflow from helper_scripts/configureExamples.sh)
- Scalable sets of input samples spanning multiple sample counts
- Equivalent Snakemake Snakefile re-implementation of the same task chain
- Per-step execution reports generated by reportGenerator.jar

## Outputs

- wms_overhead_benchmark.csv containing Watchdog and Snakemake overhead (total wall time minus summed task runtimes) per sample count
- Per-step execution reports from reportGenerator.jar
- Qualitative overhead-vs-runtime comparison corresponding to the paper's Additional file 4

## How to apply

Configure the shipped example workflows with ./helper_scripts/configureExamples.sh pointing at the Watchdog installation folder so a runnable workflow XML is available. Execute the Watchdog workflow repeatedly with ./watchdog.sh -x <xml-file> while scaling the number of input samples; the distributed Java 11 jar files are called internally by the bash scripts. Extract per-step execution reports with reportGenerator.jar, which provides basic reporting of steps performed during execution of a workflow. Re-implement the identical task chain as Snakemake rules so dependencies between tasks are automatically inferred by matching filenames, and run it over the identical sample sets. For each sample count, compute WMS overhead as total wall time minus summed task runtimes for both systems and write the comparison to wms_overhead_benchmark.csv.

## Evaluation signals

- Measured Watchdog overhead (total wall time minus summed task runtimes) remains negligible relative to total task runtime at every tested sample count
- Measured Snakemake overhead likewise remains negligible relative to total task runtime across the sample-count range
- The overhead trend qualitatively matches the comparison reported in the paper's Additional file 4
- reportGenerator.jar output covers every step of the executed workflow, confirming no task was skipped in the runtime sums
- Both systems were run over identical sample sets, so per-sample-count overhead figures are directly comparable

## Limitations

- Overhead conclusions rely on the trend across the tested sample-count range; absolute overhead values may differ on other hardware or with other task mixes
- The comparison was qualitative with respect to the paper's Additional file 4 rather than a strict numeric reproduction
- Watchdog requires JDK 11 or higher and the distributed jar files are built for Java 11; running the jar directly (java -jar jars/watchdog.jar) is discouraged because CTRL+C signals are forwarded to child processes
