# linkage-graph-spectral-eigendecomposition

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Infers diploid haplotypes by building a linkage graph from fragment data and partitioning alleles via the sign of the Fiedler (second eigenvector) vector, computed with ARPACK, using recursive spectral bisection when a block does not resolve directly.

## When to use

Use when phasing diploid SNVs from fragment files generated by WGS, Hi-C, 10X linked-reads, PacBio SMRT or Oxford Nanopore data, and you want a spectral graph-theory alternative to MEC/max-cut iterative optimization.

## When NOT to use

- The organism is polyploid or more than two haplotypes are expected — the current graph bisection model does not fit increased ploidy.
- The goal is haplotype-resolved structural variation determination — the linkage graph only supports SNPs and short insertions/deletions.
- A guarantee of an optimal phasing solution is required — SpecHap provides no optimality guarantee and interval size affects the result.

## Inputs

- bgzipped, tabix-indexed, position-sorted VCF of heterozygous variant calls
- fragment file (10X/Hi-C/new-format with 6 columns, or paired-end NGS/PacBio SMRT/ONT default format with 3 sort key columns), sorted consistently with the VCF

## Outputs

- phased VCF written to the path supplied to --out, with alleles partitioned into two haplotypes by Fiedler-vector sign

## How to apply

Prepare the input VCF (bgzipped, tabix-indexed, position-sorted) and fragment file sorted consistently ('sort -n -k6 in.frag > sorted.frag' for 10X/Hi-C/new-format fragments; 'sort -n -k3 in.frag > sorted.frag' for paired-end NGS, PacBio SMRT or ONT default format). Invoke SpecHap in phasing mode with the appropriate platform flag (e.g. --pacbio for PacBio SMRT reads), optionally constraining computation to user-defined chromosome intervals via its divide-and-conquer strategy. SpecHap builds the linkage graph, eigendecomposes it with ARPACK (arpack-ng recommended, requiring BLAS/LAPACK), and assigns alleles to haplotypes by the sign of the Fiedler vector, which acts as a min-cut heuristic on the linkage graph. When the Fiedler vector only separates variants into two sub-blocks rather than resolving the haplotype, recursively bisect those sub-blocks until the Fiedler vector yields the haplotype; prune sub-blocks of only two variants whose haplotype cannot be resolved. ExtractHair (a modified utility from HapCUT2, built with pinned htslib commit 26229a3 and samtools commit 255f97d) handles fragment processing.

## Examples

```
SpecHap --vcf /your/gzvcf/file --frag /your/fragment/file --out /phased/vcf --pacbio
```

## Evaluation signals

- The phased VCF exists at the --out path and the run completed without exceeding the usage boundary (24 CPU hours for Homo sapiens; 5 CPU days and 40GB for Ambystoma mexicanum).
- Haplotype accuracy is comparable to trio-phased ground truth (1000 Genomes Project trio-phased haplotypes for NA12878 and NA19240).
- Memory and CPU usage stay below reference envelopes, e.g. 6 CPU hours and 945MB peak memory for the ~32x PacBio SMRT Ambystoma mexicanum genome.
- Graph-cut routine runtime scales with SNV count as expected: ≤500 CPU microseconds at 500 SNVs across 10x–50x coverage profiles.

## Limitations

- No guarantee that SpecHap provides optimal solutions; the interval size parameter may affect the phasing result and a larger interval size might reduce efficiency.
- The current graph bisection model might not fit when ploidy increases; high-ploidy generalization is not implemented.
- Only SNPs and short insertions/deletions are supported; haplotype-resolved structural variation requires a refined linkage graph incorporating genome rearrangements.
- No comprehensive analysis yet of how technology-specific error in Hi-C and 10X linked-reads influences phasing quality.
