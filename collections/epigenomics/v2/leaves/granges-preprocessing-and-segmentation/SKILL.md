# granges-preprocessing-and-segmentation

## Summary

Preprocess observed genomic ranges (GRanges objects, e.g. human liver caQTL peaks and total cholesterol GWAS SNPs) and partition the genome into segments so that null range sets can be generated with block bootstrap rather than conventional shuffling, preserving local genomic correlation structure.

## When to use

Use when the task is building GRanges objects for observed range sets (e.g. caQTL peaks, GWAS SNPs) and genome segmentation needed as input to bootRanges' segmented block bootstrap for enrichment testing.

## When NOT to use

- When the goal is the conventional shuffling null itself (bootstrap.R) rather than the segmentation-and-bootstrap pipeline — shuffling is only a comparison arm here and inflates significance
- When the input data are not genomic ranges (e.g. already-aggregated overlap statistics or expression matrices), where only the downstream var.R / plotting steps apply

## Inputs

- GRanges objects for human liver caQTL peaks
- GRanges objects for SNPs associated with total cholesterol
- Genome segmentation definitions (segmentation methods evaluated in the paper)
- Block length parameters Lb (300 kb and 600 kb)

## Outputs

- Preprocessed GRanges objects ready for overlap testing
- Segmented genome used for block bootstrap
- Null range sets generated by bootRanges segmented block bootstrap
- Overlap rate and variance / z-score inputs consumed by var.R

## How to apply

First construct GRanges objects for the observed range sets — in the liver analysis, human liver caQTL peaks and SNPs associated with total cholesterol — using the paper's GRanges_construct.R preprocessing script. Next, segment the genome with the evaluated segmentation methods, choosing block lengths for the segmented block bootstrap (the paper evaluates Lb = 300 kb and 600 kb). Feed the segmented genome and block-length settings into segBootranges.R, which performs bootRanges to generate null range sets under the block bootstrap; keep the conventional shuffling alternative (bootstrap.R) only as a comparison arm, since the article shows shuffling yields overly narrow null distributions (z=18.5 vs z≈4) and over-estimates statistical significance. The decision point is block length: both 300 kb and 600 kb are evaluated and tabulated across segmentation methods before computing overlap rates and z-scores in var.R.

## Related tools

- **bootRanges** (Generates block bootstrapped null genomic ranges from the segmented genome, preserving local genomic correlation structure) — https://bioconductor.org/packages/nullranges
- **nullranges** (R/Bioconductor package hosting bootRanges functions used to perform the segmented block bootstrap (segBootranges.R)) — https://bioconductor.org/packages/nullranges

## Examples

```
Rscript script/liver/GRanges_construct.R && Rscript script/liver/segBootranges.R
```

## Evaluation signals

- GRanges objects for both liver caQTL peaks and total cholesterol SNPs are constructed without coordinate mismatches before any null generation
- Segmented block bootstrap nulls are generated at both evaluated block lengths (Lb = 300 kb and 600 kb) across the evaluated segmentation methods
- Downstream z-scores show the expected pattern: block bootstrap z-score falls near ~4 while shuffling z-score is markedly inflated near ~18.5, confirming shuffling's overly narrow null distribution
- Results are tabulated across segmentation methods and block lengths and written to liver_chol_zscores.csv

## Limitations

- Conventional shuffling or permutation schemes may result in overly narrow test statistic null distributions and over-estimation of statistical significance, so unsegmented nulls should not be trusted for inference
- Block length choice (300 kb vs 600 kb) and segmentation method both influence the resulting null distributions and z-scores and must be evaluated together
