# fragment-extraction-from-aligned-reads

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Extract variant-supporting fragment files from sorted, indexed BAM alignments and a bgzipped, indexed VCF using the modified ExtractHAIRS utility shipped with SpecHap, applying platform-specific flags for paired-end NGS, Hi-C, 10X linked-reads, PacBio SMRT and ONT data before phasing with SpecHap/HapCUT2.

## When to use

Use when sorted BAMs aligned with BWA-MEM (short reads) or minimap2 (long reads) and a bgzipped, indexed variant VCF are ready, and platform-specific fragment files must be produced as input to haplotype phasing tools.

## When NOT to use

- Input is raw FASTQ or unaligned reads — fragments can only be extracted after alignment to a reference and VCF indexing.
- Goal is phasing from population data or pedigree/trio statistical phasing — ExtractHAIRS produces read-backed fragment files for single individual haplotyping (SIH), not population-level phasing.
- Variants include structural rearrangements — the linkage graph in this pipeline supports only SNPs, short insertions and deletions.

## Inputs

- coordinate-sorted, indexed BAM of reads aligned to the human reference genome (BWA-MEM or minimap2)
- bgzipped, indexed VCF of heterozygous variant calls (e.g. trio-phased 1000 Genomes variants for HG00403, NA12878, NA19240)
- for 10X: a bgzip/tabix-indexed barcode-spanning BED file generated by BarcodeExtract, retaining only white-listed barcodes

## Outputs

- platform-specific fragment file listing variant-supporting reads/fragments (one line per fragment with alleles and positions)
- positionally sorted fragment file: 'sort -n -k6' order for 10X/Hi-C or new-format, 'sort -n -k3' order for paired-end NGS, PacBio and ONT default-format

## How to apply

First align simulated or real reads to the human reference (BWA-MEM for short reads, minimap2 for PacBio/ONT long reads) and sort/index the BAMs with samtools/htslib. Build the modified ExtractHAIRS from the SpecHap submodules: pin htslib to commit 26229a3 and samtools to 255f97d, then run 'make' in hair-src. Run extractHAIRS on the sorted BAM plus the bgzipped, indexed VCF, choosing platform flags: --hic 1 for Hi-C, --10x 1 together with a bgzip/tabix-indexed barcode-spanning BED generated by BarcodeExtract for 10X linked-reads, and --pacbio 1 or --ont 1 with --ref for long reads. Finally sort the fragment files positionally: 'sort -n -k6' for 10X/Hi-C or new-format fragments and 'sort -n -k3' for paired-end NGS, PacBio and ONT default-format fragments, ensuring fragment order matches the VCF variant order so phasing tools read coherent blocks.

## Evaluation signals

- Fragment file sort order matches VCF positional order — check that 'sort -n -k6' (10X/Hi-C/new-format) or 'sort -n -k3' (NGS/PacBio/ONT default) was applied as required before phasing.
- The VCF is bgzipped and tabix-indexed; extractHAIRS runs only with an indexed VCF and a sorted BAM present.
- For 10X inputs, the barcode BED is bgzip/tabix-indexed and fragments retain only white-listed barcodes.
- The correct platform flag was used per technology (--hic 1, --10x 1, --pacbio 1 with --ref, --ont 1 with --ref); using the wrong flag changes fragment block coordinates and degrades downstream phasing accuracy.
- Build reproducibility: submodules htslib at 26229a3 and samtools at 255f97d, with 'make' succeeding in hair-src.

## Limitations

- The fragment graph supports only SNPs, short insertions and deletions; haplotype-resolved structural variation cannot be extracted or phased in this workflow.
- Fragment sort key differs by data type and platform (column 6 for 10X/Hi-C/new-format vs column 3 for NGS/PacBio/ONT); applying the wrong key silently misorders fragments relative to the VCF.
- 10X extraction is restricted to fragments with white-listed barcodes, so reads with non-whitelisted barcodes are dropped.
