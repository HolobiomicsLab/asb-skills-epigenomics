# switch-error-rate-evaluation

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Evaluates haplotype assembly outputs by comparing each tool's phased VCF against the 1000 Genomes Project trio-phased 'ground truth', computing switch error rate, mismatch error rate, AN50, and number of phased variants for methods such as SpecHap, FastHare, HapCUT, HapCUT2, DCHap and ReFHap.

## When to use

Use when you have phased VCF outputs from haplotype assembly tools on NA12878/NA19240 WGS data (NGS, 10x, Hi-C, PacBio SMRT, ONT) and need to quantify phasing accuracy against trio-phased truth.

## When NOT to use

- No trio-phased ground truth is available for the sample (e.g. non-human or non-1000 Genomes individuals), so switch/mismatch error rates cannot be computed
- The output is haplotype-resolved structural variation calling rather than SNV/short-indel phasing — SpecHap and this SIH evaluation framework support only SNPs and short insertions/deletions
- Polyploid organisms — the graph bisection model underlying SpecHap and this diploid evaluation does not fit increased ploidy

## Inputs

- Phased VCF output from each phasing tool (SpecHap, FastHare, HapCUT, HapCUT2, DCHap, ReFHap)
- 1000 Genomes Project trio-phased haplotype ground truth for NA12878 and NA19240
- Position-sorted bgzipped VCF of trio-phased variant sets used as phasing input
- Fragment files generated by extractHAIRS per sequencing technology

## Outputs

- Switch error rate per method per sequencing technology
- Mismatch error rate per method per sequencing technology
- AN50 and number of phased variants per method per technology
- benchmark_results.tsv compiling all metrics across methods and platforms

## How to apply

Take the trio-phased high-quality variant sets for NA12878 and NA19240 from the 1000 Genome Project as ground truth and the position-sorted bgzipped VCF used as input for phasing. Run each phasing method (SpecHap, FastHare, HapCUT, HapCUT2, DCHap, ReFHap) on the same extractHAIRS-generated fragment files per technology (--hic 1, --10x 1, --pacbio 1, --ont flags), recording CPU time and peak memory. Evaluate each phased output against the ground truth to compute AN50, number of phased variants, switch error rate, and mismatch error rate. Compile all method/technology metrics into a single benchmark_results.tsv; a cell is valid only if it reports all metrics. Acceptance criterion: reproduced values should show SpecHap with less memory and CPU time while achieving accuracy comparable with state-of-the-art methods.

## Related tools

- **SpecHap** (Spectral-graph-theory phasing tool whose output VCFs are evaluated for switch/mismatch error rate against trio-phased truth) — https://github.com/deepomicslab/SpecHap
- **HapCUT2** (State-of-the-art comparator phasing tool benchmarked under the same accuracy metrics) — https://github.com/vibansal/HapCUT2
- **htslib** (Prerequisite library (plus tabix/bgzip) used for bgzipped VCF handling in the phasing/evaluation pipeline) — https://github.com/samtools/htslib

## Examples

```
SpecHap --vcf NA12878.vcf.gz --frag NA12878.pacbio.frag --out NA12878.spec hap.pacbio.vcf --pacbio
```

## Evaluation signals

- Every method/technology cell in benchmark_results.tsv reports AN50, phased variant count, switch error rate, mismatch error rate, CPU time and peak memory
- Reproduced switch and mismatch error rates are comparable across SpecHap, FastHare, HapCUT, HapCUT2, DCHap and ReFHap on the same fragment files
- SpecHap accuracy is comparable with state-of-the-art methods while consuming less memory and CPU time across all test instances
- Phased output VCF coordinates/variants are consistent with the position-sorted bgzipped input VCF and fragment ordering (sort -n -k6 for 10x/Hi-C, sort -n -k3 for NGS/PacBio/ONT)

## Limitations

- SpecHap provides no guarantee of optimal solutions; phasing results depend on the user-defined interval size, and a larger interval size might reduce efficiency
- Accuracy evaluation covers only SNPs and short insertions/deletions; haplotype-resolved structural variation is not supported
- A comprehensive analysis of the influence of technology-specific error on phasing quality for Hi-C and 10x linked-reads has not yet been conducted
