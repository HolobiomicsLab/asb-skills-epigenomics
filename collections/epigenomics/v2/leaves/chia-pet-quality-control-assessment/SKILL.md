# chia-pet-quality-control-assessment

## Summary

Automated quality control assessment embedded in ChIA-PIPE that evaluates ChIA-PET data processing quality after linker filtering, read mapping, peak calling, and loop calling, and generates .hic and .cool files for 2D contact map inspection with Juicebox and HiGlass.

## When to use

Use when processing a ChIA-PET (or related HiChIP/PLAC-seq) library through ChIA-PIPE and you need an automated QC assessment plus visualization files to judge dataset quality after the full pipeline run.

## When NOT to use

- The data are not ChIA-PET or a related chromatin-mapping assay supported by ChIA-PIPE (e.g., plain bulk ChIP-seq or ATAC-seq libraries)
- Only post-alignment BAM or pre-computed interaction matrices are available and the pipeline's full FASTQ-to-QC workflow cannot be run

## Inputs

- Paired-end ChIA-PET FASTQ files (e.g., LDK0004-ds_*.fastq.gz)
- ChIA-PIPE configuration file (example_config_file.sh)
- Reference genome for read mapping (version not specified in this section)

## Outputs

- Automated quality control assessment for the dataset
- .hic visualization input file for Juicebox 2D contact map viewing
- .cool visualization input file for HiGlass 2D contact map viewing
- Called peaks and interaction loops

## How to apply

Set up a working directory, clone ChIA-PIPE from GitHub, and locally install dependencies with local_install_chia_pipe_dependencies.sh -i ${dep_dir}. Place the FASTQ read pairs (e.g., LDK0004-ds_*.fastq.gz) into a fastq/ subdirectory as required by the configuration, then launch the complete pipeline via 0.chia_pipe_shell.sh -c example_config_file.sh (or the PBS script on HPC), which runs linker filtering, read mapping, peak calling, and loop calling in sequence. During processing, retain only unique alignments with MAPQ >= 30 and nonredundant PETs via the CPU 'dedup' module, and use only PET reads with a detected linker and genomic tags at both ends for loop detection. After the run completes, inspect the automated quality control assessment generated for the dataset, and confirm that .hic and .cool visualization input files were generated for Juicebox and HiGlass viewing.

## Examples

```
bash chia_pipe-master/0.chia_pipe_shell.sh -c chia_pipe-master/example_config_file.sh
```

## Evaluation signals

- Pipeline completes without error and produces called peaks and interaction loops for the test library
- An automated quality control assessment report is generated for the dataset after the run
- .hic and .cool visualization files are generated and render in Juicebox and HiGlass
- Retained PETs are unique alignments with MAPQ >= 30 and nonredundant (CPU dedup applied)
- Loop detection used only PET reads with a detected linker and both ends having genomic tags

## Limitations

- The reference genome version used for alignment is not specified in this section
- QC assessment is tied to the full ChIA-PIPE pipeline; the custom Python script used for E-P/P-P loop classification is not named, versioned, or hosted at a stated location
- Wall-clock/resource envelope is benchmarked at ~10 hours, 20 threads, 60 Gb RAM for a ~300 million read-pair HFFc6 CTCF HiSeq library; smaller systems may struggle with libraries of 200-400 million read pairs
