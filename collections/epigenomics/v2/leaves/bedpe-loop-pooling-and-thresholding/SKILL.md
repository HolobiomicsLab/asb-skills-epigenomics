# BEDPE loop pooling and probability thresholding

## Summary

Converts genome-wide per-pixel random-forest probability scores from Peakachu into a non-redundant set of chromatin loops by pooling scored pixels and applying a model-specific probability cutoff (e.g., 0.92 for the H3K27ac HiChIP-trained GM12878 model), yielding a BEDPE loop list.

## When to use

Use when you have raw per-pixel interaction probability scores (BEDPE) from Peakachu score_genome/score_chromosome and need to derive a final non-redundant loop set with a model-specific probability threshold.

## When NOT to use

- Per-pixel scores have not yet been generated by 'peakachu score_genome' or 'score_chromosome' — pool operates only on those outputs
- The goal is to score individual pixels rather than collapse them into non-redundant loops — use score_chromosome with --minimum-prob instead
- Working with non-Hi-C contact maps lacking a calibrated model-specific probability cutoff (cutoffs for other cell lines are in Supplementary Data 2, not the main text)

## Inputs

- BEDPE file of per-pixel random-forest probability scores from 'peakachu score_genome' (probability in 7th column, interaction frequency in final column)
- A probability cutoff appropriate to the trained model (e.g., 0.92 H3K27ac model; 0.97 CTCF model)

## Outputs

- Non-redundant BEDPE list of predicted chromatin loops with centroid loci (e.g., ~13,292 loops for GM12878 H3K27ac model at t=0.92)

## How to apply

After running 'peakachu score_genome' at 10 kb resolution with ICE-weight-normalized signals ('--clr-weight-name weight'), write raw per-pixel random-forest probabilities to a BEDPE file. Apply 'peakachu pool -t <threshold>' to select the most significant non-redundant loop pixels, choosing the cutoff calibrated per model: 0.92 for the H3K27ac HiChIP-trained model and 0.97 for the CTCF-trained model in GM12878. Verify the output BEDPE contains the random-forest probability in the 7th column and the contact-matrix interaction frequency in the final column. For the reference GM12878 case, the 0.92 cutoff applied to scores from the model trained on 6395 gm12878.mumbach.h3k27ac-hichip.hg19.bedpe loops should yield ~13,292 predicted loops.

## Related tools

- **Peakachu** (Provides the 'peakachu pool' command that selects the most significant non-redundant loops from per-pixel probability scores at a user-specified minimum-prob threshold) — https://github.com/tariks/peakachu

## Examples

```
peakachu pool -t 0.92
```

## Evaluation signals

- Output BEDPE loops carry the random-forest probability in the 7th column and contact-matrix interaction frequency in the final column
- GM12878 H3K27ac-model run at cutoff 0.92 reproduces ~13,292 loops from the same Rao2014-GM12878-MboI-allreps-filtered.10kb.cool input
- Resulting loop set shows ~65% overlap with CTCF-model predictions and ~84% single-source validation rate, consistent with published H3K27ac-model results
- All reported loop pixels have probability ≥ the chosen threshold and no redundant pixel pairs remain after pooling

## Limitations

- Probability cutoffs are model-specific (0.97 CTF vs 0.92 H3K27ac in GM12878); cutoffs for other cell lines exist only in Supplementary Data 2
- Pooled loops represent one method's loop set; Peakachu, HiCCUPS, and Fit-Hi-C each detect a unique set, so no single method captures the complete loop repertoire
- Validation rate of loop predictions can drop on enhanced/augmented (e.g., Boost-HiC boosted) Hi-C matrices depending on the augmentation rate

## Evidence

- [discussion] pool cutoff 0.92 yields ~13,292 loops: "we set the cutoff to 0.97 and 0.92 for the CTCF model and the H3K27ac model, respectively."
- [methods] pool selects non-redundant loops: "The pool function serves to select the most significant non-redundant results from per-pixel probabilities calculated by the score functions"
- [readme] chromosome-wise training avoids overfitting: "The model for every chromosome was trained using interactions from all the other 22 chromosomes in the provided bedpe file. The purpose of this is to avoid Peakachu to predict loops from the same map"
- [discussion] each method detects a unique loop set: "each method detects a unique set of chromatin loops with various distance distributions, CTCF binding, and validation ratios"
