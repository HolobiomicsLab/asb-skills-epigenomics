# bisulfite-amplicon-sequencing-methylation-data-processing

## Summary

A Bayesian calibration workflow (MethylCal, INLA-based) for correcting PCR bias in bisulfite amplicon sequencing methylation data, deriving calibration curves jointly across all CpGs in a CGI/DMR and benchmarking them against Moskalev's cubic polynomial regression (CPR).

## When to use

Use when bisulfite amplicon sequencing data include standard controls with known methylation percentages (e.g. 0-100% AMP series) and observed methylation levels need PCR-bias correction and calibration across multiple CpGs.

## When NOT to use

- The target region is a single CpG with no standard controls of known methylation percentage — the method requires five standard controls (e.g. 0/25/50/75/100%) to derive calibration curves
- The goal is genome-scale methylation calling from bisulfite reads rather than PCR-bias correction of targeted amplicon assays
- Data were not generated by bisulfite amplicon sequencing (e.g. pyrosequencing or array methylation levels), since the calibration model is specific to amplification-induced bias

## Inputs

- Raw bisulfite amplicon sequencing methylation data for standard controls with known AMP percentages (packaged BWS_data, Celiac_data)
- Case/control sample methylation levels (e.g. 15 healthy controls and 18 potential BWS patients; 17 individuals with celiac disease)
- AMP vector of standard-control methylation percentages per assay
- MiSeq-sequenced amplicons targeting CpG islands on the SDHC promoter and six imprinting DMRs

## Outputs

- Calibration curves per assay with goodness-of-fit measures (in-sample RSS) from MethylCalCalibrationPlot and MoskalevCalibrationPlot
- Cross-validation measures (MSEP, CV-index) under three removal scenarios (CpG-AMP combination, each CpG, each AMP)
- Corrected methylation levels for case and control samples (via TableFormatting, a table matching the uploaded data format)
- Outlier detections per CpG-AMP combination

## How to apply

Load the MethylCal R package (with INLA installed manually from inla.r-inla-download.org) and transform raw data with Formatting(), passing AMP = c(0, 25, 50, 75, 100) for BWS_data and AMP = c(0, 12.5, 25, 37.5, 50, 62.5, 87.5, 100) for celiac data. Explore standard controls with ExploratoryPlot, then fit the joint Bayesian calibration of all CpGs with MethylCalCalibrationPlot (INLA-based), using MethylCalCalibrationOutlierPlot to detect outliers via a posterior predictive interval with l = Q1 − 1.5IQR and u = Q3 + 1.5IQR before refitting without them. Compare goodness of fit against Moskalev's CPR (MoskalevCalibrationPlot) and Warnecke (WarneckeCalibrationPlot); cross-validation is performed by removing a CpG-AMP combination, each CpG one-at-a-time, or each AMP separately, reporting RSS, MSEP and CV-index. Correct case/control methylation levels with MethycalCorrection or MoskalevCorrection and reshape results with TableFormatting().

## Examples

```
data(BWS_data); AMP = c(0, 25, 50, 75, 100); data = Formatting(BWS_data, AMP = AMP, n_Control = 15, n_Case = 18); corr_data = MethylCalCorrection(data, Target = "KCNQ1OT1", n_Control = 15, n_Case = 18)
```

## Evaluation signals

- Tabulated per-assay RSS values from MethylCal and Moskalev's CPR must all fall in [0, 1]
- Every CV-index computed in the leave-one-out cross-validation must be <= 1
- MethylCal's best DIC-selected model should achieve a lower leave-one-out MSEP than Moskalev's CPR by several orders of magnitude when cross-validation removes a CpG-AMP combination or a CpG
- Corrected output from MethylCalCorrection reformatted by TableFormatting must have the same format as the uploaded data set (same columns as the input given n_Control and n_Case)
- Replicating the README example should reproduce Figure 3 C&D of Ochoa et al. (2019)

## Limitations

- CpGs 21–23 had to be removed from the PLAGL1 assay based on visual inspection of the data, so the method may require manual CpG filtering
- No software version numbers are stated for MethylCal or Moskalev's CPR, and no version of R or of the MethylCal package is stated
- R-INLA must be installed manually and is not an automatic dependency (unlike lattice and latticeExtra)
- Outlier detection depends on the posterior predictive interval [l, u] with l = Q1 − 1.5IQR and u = Q3 + 1.5IQR, so mis-specified quartiles affect detection
