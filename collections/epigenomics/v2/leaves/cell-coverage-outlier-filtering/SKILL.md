# cell-coverage-outlier-filtering

## Summary

ChromSCape's quality-control step that removes low-coverage and coverage-outlier cells from a single-cell epigenomic count matrix by applying a minimum read-count threshold per cell (e.g. 1600 unique reads) and dropping cells in the top 5% of coverage before downstream normalization.

## When to use

Use when a raw single-cell ChIP-seq/scATAC-seq count matrix (cells x bins/peaks/TSS regions) contains low-quality or extreme-coverage cells that must be filtered before PCA, t-SNE/UMAP, or clustering.

## When NOT to use

- Input is already a quality-filtered count matrix with cell QC previously applied — reapplying thresholds would discard additional valid cells
- The goal is to filter genomic regions/peaks (e.g. regions detected in at least 1% of cells) rather than filter cells
- Data are bulk ChIP-seq or other non-single-cell data where per-cell coverage thresholds do not apply

## Inputs

- single-cell count matrix (cells x genomic bins/peaks/TSS regions) generated by ChromSCape from gzipped single-cell BED or BAM files
- per-cell total read/coverage counts
- user-defined minimum read count threshold per cell (e.g. 1600 unique reads)
- upper-percentile coverage cutoff (default top 5%)

## Outputs

- filtered cell-by-feature count matrix retaining only cells passing the minimum-coverage and top-5%-coverage criteria
- normalized count matrix (normalized by total read count and region size), e.g. count_matrix_normalized.tsv

## How to apply

After ChromSCape generates the count matrix by aggregating signal into successive genomic bins (e.g. 50,000 bp bins for broad marks like H3K27me3 or 5,000 bp bins/TSS regions for sharp marks), apply a user-defined minimum read count per cell threshold — in the article's benchmark, cells were required to have a minimum coverage of 1600 unique reads. In the same QC pass, remove cells with the top 5% coverage to eliminate coverage outliers. The rationale is that both low-coverage cells (too sparse to reflect the epigenome) and extreme-coverage cells (e.g. doublets or mapping artifacts) distort downstream dimensionality reduction and differential enrichment. After filtering, normalize the retained matrix by total read count and region size. In the paired scChIPseq_DataEngineering pipeline, deduplication (PCR, RT, and window duplicates) is performed upstream so that read counts reflect unique reads per cell.

- **ChromSCape** (Shiny/R Bioconductor application that implements the QC cell filter (minimum read count per cell, top-percentile removal) on the aggregated count matrix) — https://github.com/vallotlab/ChromSCape_benchmarking

## Evaluation signals

- Every retained cell has total unique read coverage above the minimum threshold (1600 unique reads in the benchmark setting)
- No retained cell falls within the top 5% of the coverage distribution (outlier coverage removed)
- The output matrix dimensions match the expected number of retained cells and regions after both cell and region filters
- Post-filter values in count_matrix_normalized.tsv reflect scaling by total read count and region size
- Per-cell coverage histogram after filtering shows a truncated distribution with both the low tail and the extreme high tail removed

## Limitations

- The minimum-read-count threshold and upper percentile are user-defined, so over- or under-aggressive thresholds silently change which cells are retained; the top-5% default may not suit all datasets
- Additional filtering of benchmark cells required prior manual removal of known CNV segments (77 Mbp in MDA-MB-468), so coverage filtering alone does not resolve copy-number-driven artifacts
- Benchmark comparison scope was limited (1287 QC-passing cells; random sub-sampling of 500 MDA-MB-468 cells), so threshold behavior at larger scale is unverified
