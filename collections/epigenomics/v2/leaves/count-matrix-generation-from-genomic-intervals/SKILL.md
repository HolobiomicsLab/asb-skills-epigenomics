# Count matrix generation from genomic intervals

## Summary

Builds a per-cell x region count matrix from sparse single-cell epigenomic data (e.g. scChIP-seq, scCUT&Tag, scChIC-seq) by aggregating single-cell BED signal into genomic bins, user-supplied peaks, or regions around gene Transcription Start Sites within ChromSCape (Shiny/R, Bioconductor).

## When to use

Use when starting from gzipped single-cell BED files of sparse histone-modification or chromatin-accessibility data and a per-cell count matrix is needed as the entry point for QC filtering, PCA, UMAP and clustering.

## When NOT to use

- Input is already a count matrix in 50 kbp bins — it can be inputted directly into ChromSCape and re-counting is unnecessary
- Data are high-coverage bulk ChIP-seq or non-epigenomic (e.g. RNA-seq); existing bulk ChIP-seq tools vs this sparse single-cell workflow target different data regimes
- Peak-region aggregation is desired but no BED peak file can be provided — ChromSCape requires the user to supply peaks for that mode

## Inputs

- Gzipped single-cell BED files (one per cell, barcode-labeled) from GEO accessions (GSE124680, GSE124690, GSE105012)
- User-supplied BED peak file (required for the peaks aggregation option)
- Count matrices in 50 kbp bins produced by the scChIPseq_DataEngineering pipeline
- Optionally, a BED file of regions to exclude (e.g. CNV segments such as MDA-MB-468 77 Mbp regions)

## Outputs

- Per-cell x region count matrix (genes TSS ±2500 bp or 50 kbp bins)
- Coverage/read-count statistics per cell for QC thresholding
- Filtered count matrix passed to PCA (50 first PCs) and UMAP/t-SNE visualization

## How to apply

Load the gzipped single-cell BED files (e.g. GSE124680/GSE124690 scCUT&Tag H3K27me3, GSE105012 scChIC-seq H3K4me3) into ChromSCape and choose the aggregation strategy per mark: signal around gene Transcription Start Sites (±2500 bp) for H3K27me3 scCUT&Tag, or successive 50 kbp genomic bins for H3K4me3 scChIC-seq; user-provided BED peak files are required for the peaks option. After counting, apply QC filtering — a minimum coverage of 1600 unique reads per cell, removal of the top 5% coverage cells, and keeping regions detected in at least 1% of cells. The rationale is that single-cell histone modification data are sparse and low-coverage, so interval-based aggregation (bins/TSS) trades resolution for signal; count matrices in 50 kbp bins generated by the scChIPseq_DataEngineering pipeline (barcode mapping, trimming, STAR mapping, RT/PCR/window duplicate removal) can also be fed directly into ChromSCape. Downstream success of the matrix is judged by ARI = 0.976 for K562-vs-H1 separation and 7 visible UMAP clusters.

## Related tools

- **ChromSCape** (Shiny/R Bioconductor application that creates the count matrix by aggregating single-cell signal into genomic bins, user-provided peaks, or gene TSS regions, then applies QC filtering) — https://github.com/vallotlab/ChromSCape_benchmarking


## Evaluation signals

- Matrix dimensions match cells passing QC: min 1600 unique reads per cell, top 5% coverage cells removed, regions kept only if detected in at least 1% of cells
- Downstream scCUT&Tag K562/H1 separation reproduces ARI = 0.976 against ground-truth labels
- scChIC-seq H3K4me3 UMAP shows the 7 expected clusters matching the original study
- PCA embedding retains exactly the first 50 centered PCs for further analysis
- For pipeline-produced matrices, RT, PCR and window duplicates have been removed before counting

## Limitations

- The peak calling module requires user-supplied BAM files (one per sample, reads labeled with barcode ID) and MACS2, whose version is not specified; BAM files are not deposited for all benchmarking datasets
- For CNV-bearing cell lines (e.g. MDA-MB-468), known CNV segments (77 Mbp) must be removed prior to analysis as an extra manual curation step
- Benchmark comparison was restricted to a subsampled set of 1287 cells (500 MDA-MB-468 cells), limiting the scope under which matrix quality was validated
