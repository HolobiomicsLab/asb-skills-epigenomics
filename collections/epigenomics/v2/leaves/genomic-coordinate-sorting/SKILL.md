# genomic-coordinate-sorting

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Position-sorts fragment files so that genomic coordinates follow the same variant ordering as the VCF, a prerequisite for SpecHap's linkage-graph construction, where nodes are heterozygous loci and edges carry truncated log-likelihood-ratio weights.

## When to use

Use when a fragment file produced by ExtractHair (modified from HapCUT2) must be sorted consistently with VCF variant order before SpecHap linkage-graph construction or haplotype phasing.

## When NOT to use

- The fragment file is already confirmed sorted consistently with the VCF order — re-sorting adds no information and risks reordering new-format fragment blocks incorrectly.
- The goal is haplotype assembly itself (allele partitioning via the Fiedler Vector) rather than input-order normalization — use the SpecHap phasing workflow instead.

## Inputs

- Fragment file generated by extractHAIRS (10X/Hi-C or new-format fragments; paired-end NGS; PacBio SMRT; Oxford Nanopore default format)
- bgzipped VCF of heterozygous variant calls defining the reference variant order

## Outputs

- Position-sorted fragment file whose locus order matches the VCF variant order, ready for linkage-graph parsing

## How to apply

Confirm the fragment file generated by extractHAIRS (the ExtractHair utility modified from HapCUT2) was sorted consistently with the VCF order: apply `sort -n -k6` for 10X/Hi-C or new-format fragments, and `sort -n -k3` for paired-end NGS, PacBio SMRT, or Oxford Nanopore default-format fragments. The rationale is that SpecHap defines graph nodes as heterozygous variant loci covered by fragments and co-occurrence edges only if positions are consistent between the fragment file and the VCF; misalignment of coordinates would silently drop or misplace edges. After sorting, parse the file position-wise so every pair of loci co-observed on the same fragment can be keyed by the same locus identifiers used in the VCF. The sorted file then feeds the downstream step that computes log-likelihood ratios from fragment Phred probabilities and emits linkage_graph.tsv as a tab-delimited table.

## Related tools

- **ExtractHair (from HapCUT2)** (Produces the fragment file that must be position-sorted to match the VCF order before graph construction) — https://github.com/vibansal/HapCUT2
- **SpecHap** (Consumes the position-sorted fragment file to build the weighted undirected linkage graph for spectral phasing) — https://github.com/deepomicslab/SpecHap

## Examples

```
sort -n -k6 fragments.txt > fragments.sorted.txt
```

## Evaluation signals

- Verify the numeric coordinate column used for sorting (column 6 for 10X/Hi-C or new-format fragments, column 3 for paired-end NGS/PacBio/ONT default format) is monotonically non-decreasing in the output file.
- Cross-check that the set of genomic positions appearing in the sorted fragment file is identical to the heterozygous loci in the VCF that are covered by fragments.
- Confirm the downstream linkage_graph.tsv is tab-delimited and every edge weight is a finite numeric log-likelihood-ratio value (max(log(p(H1)/p(H2)), 0)).
- Confirm the node set of the emitted graph matches the heterozygous loci covered by fragments in the input file — a mismatch often indicates a sort-order inconsistency with the VCF.
- Check no fragments were lost or duplicated during sorting: fragment counts before and after the sort must be equal.

## Limitations

- The sort key differs by platform: 10X/Hi-C or new-format fragments sort on column 6, whereas paired-end NGS, PacBio SMRT, and Oxford Nanopore default formats sort on column 3 — applying the wrong key silently mis-sorts.
- SpecHap's input requires at least a fragment file and a bgzipped VCF; sorting alone does not substitute for this preprocessing.
- No software version is stated for SpecHap, so sort/format compatibility with a given ExtractHair revision should be re-verified.
