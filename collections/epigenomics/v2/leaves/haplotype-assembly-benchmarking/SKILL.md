# haplotype-assembly-benchmarking

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Benchmark diploid haplotype-assembly (SIH) tools such as SpecHap against FastHare, HapCUT, HapCUT2, DCHap and ReFHap by running each on identical fragment files, recording CPU time and peak memory, and scoring phased VCFs against 1000 Genomes trio-phased ground truth (AN50, phased variant count, switch and mismatch error rates).

## When to use

Use when comparing phasing algorithms' runtime, memory, and accuracy across NGS, 10x linked-read, Hi-C, PacBio SMRT or ONT data, or when reproducing a haplotype assembly benchmark table for samples like NA12878/NA19240/HG00403.

## When NOT to use

- The task is de novo phasing or pedigree/trio statistical phasing rather than single-individual haplotype assembly from read-backed fragments
- Haplotype-resolved structural variation or polyploid (non-diploid) phasing is required — the article states the graph bisection model does not fit increased ploidy and SVs are not supported
- Only variant calling or read alignment is needed without any fragment-to-haplotype assignment step

## Inputs

- bgzipped, position-sorted VCF of heterozygous variants (e.g. trio-phased 1000 Genomes variant sets for NA12878/NA19240)
- fragment files generated by extractHAIRS from sorted BAMs (technology-specific flags)
- bgzipped/tabix-indexed barcode-spanning BED from BarcodeExtract for 10x linked reads
- sorted/indexed BAM alignments (BWA-MEM for short reads, minimap2 for long reads) for simulated or real WGS data

## Outputs

- phased VCF per tool per technology (e.g. SpecHap --out phased vcf)
- benchmark_results.tsv with AN50, phased variant count, switch error rate, mismatch error rate, CPU time and peak memory per method/technology cell
- benchmark_comparison.csv tabulating accuracy plus runtime per tool and coverage (10x/30x/50x)

## How to apply

Build SpecHap from source (cmake && make) with prerequisites arpack-ng (bootstrap; configure --enable-icb after installing BLAS/LAPACK) and htslib (autoheader; autoconf; configure; make install), plus the modified ExtractHair from pinned submodules (htslib at 26229a3, samtools at 255f97d) built with make in hair-src. Generate fragment files per technology with extractHAIRS using technology-specific flags (--hic 1 for Hi-C; --10x 1 plus a bgzipped/tabixed barcode-spanning BED from BarcodeExtract for 10x; --pacbio 1 or --ont plus --ref for PacBio SMRT/ONT), keeping only white-listed barcodes for 10x linked reads. Sort fragments consistently with the position-sorted bgzipped VCF: 'sort -n -k6' for 10x/Hi-C/new-format fragments and 'sort -n -k3' for paired-end NGS, PacBio and ONT default format. Run SpecHap and every baseline (FastHare, HapCUT, HapCUT2, DCHap, ReFHap) on the same fragment files and the trio-phased 1000 Genomes variant sets, recording CPU time and peak memory per run, then evaluate each phased VCF against the trio ground truth for AN50, phased variant count, switch error rate and mismatch error rate. Accept the benchmark only if every method/technology cell reports all metrics and reproduced values show SpecHap using less memory and CPU time with accuracy comparable to state-of-the-art.


## Evaluation signals

- Every method/technology cell in benchmark_results.tsv contains all six metrics: AN50, phased variant count, switch error rate, mismatch error rate, CPU time, peak memory
- Reproduced table shows SpecHap with lower CPU time and memory than baselines while accuracy is comparable (e.g. ~13 CPU minutes, 120MB peak on ~44x PacBio NA12878; ~40x faster than HapCUT2, ~100x faster than ReFHap, as fast as FastHare on simulated PacBio)
- Fragment files are positionally consistent with the bgzipped VCF (verify sort key: -k6 for 10x/Hi-C/new format, -k3 for paired-end NGS/PacBio/ONT default)
- Each phased output evaluated against the same 1000 Genomes trio-phased ground truth yields switch/mismatch error rates in the same range as the paper
- All tools receive the identical fragment file and variant set per condition, so any performance difference is attributable to the phasing algorithm

## Limitations

- SpecHap provides no guarantee of optimal solutions and the user-defined interval size can affect both phasing results and efficiency (larger intervals may reduce efficiency)
- Current graph bisection model does not fit increased ploidy; SIH tools including SpecHap support only SNPs and short indels, not haplotype-resolved structural variation
- No software version stated for SpecHap and no comprehensive analysis of technology-specific error for Hi-C and 10x linked-reads phasing quality
- Other four packages either did not support a specific data type or failed within usage boundaries (24 CPU hours for Homo sapiens, 5 CPU days and 40GB for Ambystoma mexicanum), so baseline cells can be legitimately missing
